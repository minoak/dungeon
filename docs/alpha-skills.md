# 원더랜드 스킬 알파 v0.1

2026-09-10. 기준선 `78fbe84` / `compose-v0.4` 위에 선택 기능으로 구현했다.
원본 제안은 [알파 테스트 계획서](../design/drafts/WONDERLAND_ALPHA_SKILL_TEST_PLAN_2026-09-10_v0.1.md),
실제 구현 규칙과 검증 범위는 이 문서를 따른다.

**기술 연결 검증은 완료했다. 실제 LLM의 행동 다양성·관전 재미·5층 밸런스는 아직 검증하지 않았다.**
기본 스위치는 모두 OFF이며, 기존 프롬프트 파일과 COMMON 10개는 그대로다.

## 실행

### 화면으로 시작하기

`wonderland.bat` → **A: SKILL ALPHA** → **알파 파티 꾸미기** → 파티 선택 → **알파 원정 시작 → 관전**.
기존 **L: LAUNCHER**에서도 **스킬 알파 시작** 버튼이나 던전 옵션의 **원정 모드**로 고를 수 있다.

알파는 스킬·TRPG 전투·랜덤 획득을 모두 켜고 던전 1~5층, 최대 600틱으로 실행한다.
두뇌·시드·맵 크기·파티는 화면에서 고른다. 마을과 솔로 모드는 사용하지 않는다.
일반판을 고르면 세 알파 플래그를 모두 끈다. 진행 중인 판의 규칙은 바뀌지 않는다.

시작 전에는 각 모험가의 스킬 효과와 소모를 미리 본다. 시작 후에는 기존 실시간 관전 화면으로 자동 이동한다.
화면 상단에 알파 표식, 모험가 카드에 **보유 스킬·효과·남은 재사용 대기**, 전투 기록에 **명중 주사위·기준값·HP 소모**가 나온다.
3층에서 얻은 스킬은 카드와 층 진입 기록에 표시한다. 되감으면 당시 보유 상태로 돌아간다. 옛 뷰어도 같은 설명을 쓴다.

웹 런처로 시작한 판은 기존처럼 `state/`에 기록하고 다음 판 시작 시 `runs/`에 보존한다.
알파 판은 영속 도감에 누적하지 않는다. 별도로 실험 파일을 모으려면 아래 CLI를 사용한다.
규칙 두뇌(dummy)는 스킬을 직접 고르지 않으므로 실제 사용 관전에는 Gemini 또는 Claude가 필요하다.

### 명령줄로 비교 실험하기

프로젝트 폴더에서 아래처럼 실행한다. CLI의 매 판은 새 `state_alpha/날짜-arm-seed/` 폴더에 저장된다.
기존 `state/`·`runs/`·영속 도감을 덮어쓰지 않는다. `--output`을 지정해도 기존 폴더는 거절한다.

```powershell
# 규칙 두뇌로 실행 경로 확인. 이 두뇌는 스킬을 고르도록 개조하지 않았다.
python run_skill_alpha.py --arm full --backend dummy --seed 7 --turns 600

# 실제 LLM 판. 기존 claude CLI를 사용한다.
python run_skill_alpha.py --arm full --backend claude_cli --seed 7 --turns 600

# 동일한 파티·시드·두뇌로 대조군
python run_skill_alpha.py --arm baseline --backend claude_cli --seed 7 --turns 600

# 기존에 사용하던 API로 명시적으로 실행할 때
python run_skill_alpha.py --arm full --backend gemini_api --seed 7 --turns 600
```

`--party 파티.json`으로 동일한 캐릭터 구성을 지정할 수 있다. API 키는 기존 `.env` 로더를 사용하며
코드·스트림에는 기록하지 않는다. 환경변수 방식으로 직접 실행하려면 **새 러너를 시작하기 전에** 아래 값을 설정한다.
이미 실행 중인 판에는 적용되지 않는다. `run_skill_alpha.py`는 이 설정과 출력 폴더 분리를 대신한다.

화면 연결 검증: `python verify_skill_launcher.py`, `python verify_launcher.py`,
`cd game; npm run build; node verify/alpha.mjs`. 브라우저 검증은 임시 상태 폴더와 dummy를 쓰고,
3층 획득·스킬 사용·되감기는 엔진이 만든 고정 검증 장면으로 확인한다. 실제 LLM의 행동 평가와는 별개다.

| 실행군 | SKILLS | TRPG_COMBAT | RANDOM_SKILL | 비교 목적 |
|---|---:|---:|---:|---|
| baseline | 0 | 0 | 0 | 기존 compose-v0.4 |
| combat | 0 | 1 | 0 | 전투 판정 변경만 |
| skills | 1 | 0 | 0 | 기존 전투 + 고정 수치 스킬 |
| preset | 1 | 1 | 0 | TRPG + 프리셋 스킬 |
| full | 1 | 1 | 1 | 위 구성 + 3층 랜덤 획득 |

환경변수 이름은 `DUNGEON_SKILLS`, `DUNGEON_TRPG_COMBAT`, `DUNGEON_RANDOM_SKILL`이고 모두 기본 `0`이다.
스킬은 compose 모드가 필요하다. 랜덤 생성 함수는 독립적으로 쓸 수 있지만 **게임 내 획득·사용은 SKILLS가 필요**하다.
RANDOM_SKILL만 켜면 기존 게임을 유지하며 메타에 `random_skill_effective:false`를 적는다.
TRPG_COMBAT만 켜는 것은 가능하다. 기존 STATUS 스위치를 꺼도 스킬이 직접 부여한 출혈·둔화는 작동한다.

## 첫 스킬셋

| 슬롯 순서 | 스킬 |
|---|---|
| 1 | 밀어베기 / 강타 |
| 2 | 출혈베기 / 응급처치 |
| 3 | 응급처치 / 밀어베기 |

이 배치는 직업 목표를 부여하지 않는 실험 프리셋이다. 4번째 슬롯부터 반복한다.
알파 ON이면 파티 JSON의 선택 필드 `"skills": ["push_slash", "first_aid"]`로 덮어쓸 수 있다.
시작 스킬은 최대 3개, 빈 목록도 허용한다. 스킬 제작·배정 UI는 추가하지 않았다.

| ID | 효과 | 주요 제약 |
|---|---|---|
| push_slash | STR 명중 후 1d6 피해 + 1칸 밀침 | 사거리 1, 밀침 STR 내성, 재사용 2행동 |
| heavy_strike | STR 명중 후 2d6 피해 | 사거리 1, HP 2 지불, 재사용 2행동 |
| first_aid | 1d6 회복, 최대 HP까지 | 자신 또는 살아있는 대상, 사거리 1, 재사용 2행동 |
| bleeding_cut | DEX 명중 후 1d4 피해 + 출혈 | 사거리 1, 출혈 DEX 내성, 재사용 2행동 |

`guard`는 보류했다. 계획서의 최소 효과 목록에 방어 효과가 없어, 이 알파에서는 제안된 네 효과로 가능한 네 프리셋을 먼저 검증한다.

## 판정 규칙

- d20은 20면체 주사위다. Attack Roll은 `d20 + STR/DEX`를 AC(맞히기 어려운 정도)와 비교한다.
  기본 전투에도 있던 이 구조를 재사용했다.
- TRPG ON은 자연 1 자동 실패·자연 20 명중, 피해 주사위, 중독 공격자의 불리굴림을 적용한다.
  기습의 유리굴림과 불리가 함께 있으면 상쇄한다. 중첩하지 않는다.
- 기존 기본 공격 피해 4는 `1d6+1`, 피해 3은 `1d4+1`로 변환한다. 일반 공격의 평균이 기존보다 0.5 높아진다.
  치명타는 피해 주사위 개수를 두 배로 하고, 장비 보정은 한 번 더한다. 기존 기습 추가 피해·각성·턴 스킵은 유지한다.
- DC는 효과를 버텨내기 위한 기준값이다. 스킬 DC는 `10 + 시전자 능력 보정`.
  Saving Throw(내성)는 대상이 `d20 + 지정 능력`을 굴려 DC 이상이면 저항하는 방식이다. 동률은 대상의 저항 성공이다.
  명중 후 부가 효과의 내성을 통과해도 이미 받은 피해는 취소하지 않는다.
- 몬스터의 알파 STR은 기존 `atk`, DEX는 `max(0, ac-10)`으로 정했다. 별도 6능력치는 도입하지 않았다.
- TRPG OFF + SKILLS ON은 기존식 명중 판정, 피해·회복 주사위의 평균 반올림 고정값을 쓴다.
  부가 내성은 생략하며, 내성형 스킬의 주 판정은 명중 판정으로 대체한다. 이 조합은 스킬 추가 영향만 관찰하기 위한 비교군이다.
- 출혈은 기존 규칙처럼 **이동 걸음에 따라** 피해를 낸다. 봇은 기존 상태 태그/걸음 처리, 몬스터는 같은 걸음 주기를 사용한다.
  몬스터 출혈은 해당 몬스터의 이동 이후 처리하며 출혈 없는 판은 기존 몬스터 턴을 그대로 따른다.
- 밀침은 벽·다른 몸을 통과하지 않는다. 밀침이 막혀도 먼저 발생한 피해를 되돌리지 않는다.
  밀린 봇은 기존 칸 진입 함정·출혈 처리와 피격 중단 규칙을 거친다. 몬스터의 강제 밀침은 출혈 걸음으로 세지 않는다.

## 행동·대기시간

스킬은 COMMON과 같은 `type + target` 문법이다. 보유하지 않은 ID는 파서에서 기존 폴백으로 보내고,
직접 엔진에 잘못된 ID를 보내도 비용 없이 실패한다. 관측에는 보유 스킬의 효과·사거리·제약·남은 대기시간만 짧게 제시한다.
프롬프트의 선택 문구는 스킬 ON일 때만 COMMON 또는 SKILL로 바꾼다.

사거리 밖이면 기존 BFS와 자동 접근을 쓴다. 접근 시작·보행에서는 스킬 비용을 내지 않고,
실행 직전에 대상·보유·HP·조건·대기시간을 다시 검사한다. 사선도 필요하므로 동료가 벽 너머 보인다고 바로 치유하지는 못한다.

재사용 2행동은 **사용 이후 유효하게 끝낸 다른 행동 두 번**을 뜻한다.
접근 걸음·진행 중 대기/휴식·조건 실패·중단된 이동은 세지 않는다.
명중 판정을 실제로 했다가 빗나간 공격, 실제 스킬 시도, 빈 결과의 유효한 수색은 센다.
스킬 자체의 새 대기시간은 사용한 순간 감소시키지 않는다. 빗나감/저항/유효하지만 효과 없는 사용도 HP·대기시간을 지불한다.
HP 비용은 생존할 수 있을 때만 허용한다. 대기시간·스킬·생성 정의는 층을 넘어 보존한다.

## 랜덤 생성과 비용

3층 첫 입장 때 인당 한 번, 예산 5로 스킬 하나를 받는다. 캐릭터별 시드 파생과 별도 RNG를 사용해
스킬을 뽑는 행위가 던전 배치·전투의 난수를 소모하지 않는다. 같은 시드·예산·구성요소 풀·버전이면 같은 정의와 ID다.

`skill_schema.py`의 효과/패널티/호환성/비용 계산을 프리셋과 생성기가 공유한다.
효과는 damage/heal/push/bleed, 패널티는 hp_cost/cooldown/self_status/condition이다.
회복+공격 효과, 자신 밀치기, 출혈 중인 대상에게 출혈만 다시 주는 조건부 스킬 같은 조합은 거절한다.
불가능한 예산은 최대 128회 후보 검사 후 오류를 반환하며 무한 재시도하지 않는다.

`cost`는 **설계 예산**이며 매 사용마다 소모되는 MP가 아니다.
현재 비용은 기대 피해/회복량 × 사거리·판정 배율 + 부가 효과 − 제약 환급으로 계산한다.
환급은 총효과 비용의 절반까지만 인정한다. 수치는 임시 실험값이며 실제 효율과의 상관은 아직 검증하지 않았다.
이름은 코드 템플릿으로 만든다. 수치 생성에 LLM을 사용하지 않는다.

## 기록과 분석

`run_meta.alpha`에 버전·플래그·프리셋·획득 층·예산·대기시간 기준을 남긴다.
봇 스냅샷에는 보유/생성 스킬과 대기시간, 3층 `level.skill_acquisitions`에는 전체 생성 정의를 기록한다.
기존 `tick.events`에 원래 type과 효과를 두고 `tick.skill_events`에 굴림·효과·resolution을 추가한다.
모든 하위 기록은 원래 `action_id`를 `parent_action_id`로 참조한다. 예전 소비자는 새 필드를 무시할 수 있다.
양쪽 관전 화면과 단일 HTML 리플레이에 스킬 결과를 표시한다.

```powershell
python analyze_skills.py "A폴더/stream.jsonl" "B폴더/stream.jsonl"
python analyze_skills.py "B폴더/stream.jsonl" --json
python make_replay_viewer.py "B폴더/stream.jsonl" -o "B폴더/replay.html"
```

분석은 접수된 결정을 기준으로 attack/COMMON/SKILL 비율, 캐릭터별 분포, 획득 전후 비율,
행동 종류 수, 엔트로피(선택이 여러 행동에 얼마나 고르게 분산됐는지), 생존률, HP 비용·회복량을 계산한다.
접근 걸음을 새 goto 결정으로 더하지 않는다. 전투 길이는 **전투 이벤트가 연속된 틱 수**라는 관측 지표다.
실제 교전 구간과 다를 수 있다. 획득 전후 표에는 분모인 결정 수도 함께 보인다.
새 전술·인상적인 사건·재미와 실패의 맥락은 사람이 리플레이에서 판단해야 한다.

원본 계획의 baseline/full 비교만으로는 전투 변경과 스킬 추가의 영향을 구분할 수 없다.
같은 파티·시드·모델·턴 한도로 baseline/combat/preset/full을 함께 비교하면 원인을 더 잘 나눌 수 있다.
dummy/fixture 판단의 통계는 플레이 성공 근거로 사용하지 않는다.
