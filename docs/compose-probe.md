# 조합형 행동으로 원정 실행하기

2026-09-10. 프롬프트 선행 프로브를 거쳐 본 구현과 **선택적 반응·관전 집계**를 연결했다. 현재 행동 프로필은 `compose-v0.5`(2026-09-11 D48: `follow` 제거 — 동행은 `goto b<char>`로 한 번 걷고 재판단), 관측 계약은 `compose-v0.4`, 반응 계약은 `social-v0.4`다.

1. 웹 론처의 새 원정에서 파티를 고르고 던전 옵션으로 이동한다.
2. 조합형은 기본 적용된다. 따로 프롬프트나 행동 방식을 고를 필요가 없다.
3. 두뇌·맵·시드를 확인하고 **원정 시작**을 누른다.

웹 론처는 방식 선택 없이 조합형으로 시작한다. 이전에 열어 둔 론처 화면은 새로고침하면 갱신된다. 이번 변경은 다음 새 원정부터 적용된다.

## 연결한 범위

- COMMON 9개 행동과 현재 대상 목록을 따로 제시한다. 번호로 완성된 행동을 고르지 않는다.
- `self`는 자신, `w...`는 이번 관측의 길, `i1/i2/i3`은 자신의 물약 묶음/착용 무기/착용 방어구다.
- `use`로 사물 기능 사용과 소지품 사용을 통합한다. 자신·동료·몬스터에게 물약을 사용하면 해당 대상의 HP가 회복되고 한 병 소모된다. 효과 없는 대상에 쓰면 소지품을 보존한다.
- 알려진 대상과 행동의 조합은 파서에서 제한하지 않는다. 피해를 입는 사람·몬스터, 소지품을 받는 사람, 기능이 있는 사물 등의 실제 성질로 결과를 판정한다.
- `search/attack/use/give/bond`는 실행 거리까지 먼저 접근한다. 피격·새 발견·길막힘·대상 소실이면 중단하고 재판단한다. 걸음과 효과를 같은 틱에 겹치지 않으며 도착 뒤 다시 검사한다.
- `then`도 같은 COMMON과 대상·소지품 형식으로 최대 2수를 받는다. 이동 전 길 ID가 만료되거나 요청한 물건이 사라지면 계획을 접고 같은 틱에 새 판단을 한다.
- 잘못된 ID와 효과 없는 조합을 구별한다. 입력 오류에는 원래 요청과 당시 ID 목록을 남기고 같은 결정에서 규칙 두뇌로 대체한다.

- 실제로 받은 말·건네기·친목·동료의 물약 사용에 사건 ID를 붙인다. 다음 행동 판단에서 한 사건에 선택적으로 like/dislike를 남길 수 있다. 화면에는 사건 원문과 캐릭터별·층별·원정 전체 집계를 표시하며, 집계 수치는 모델에 전달하지 않는다([상세 안내](reactions.md)).

`search self`는 기존 주변 수색이며, 다른 대상 조사는 현재 별도 새 정보가 없으면 `no_effect`다. `follow`는 2026-09-11(D48)에 COMMON에서 뺐다 — 보이는 사람에게는 `goto`로 간다(곁에 닿으면 끝, 다시 판단). 엔진의 follow order는 메뉴형·구판 리플레이용으로만 남는다.

## 프롬프트와 비교 기준

실행 지침은 [adventurer_prompt.md](../adventurer_prompt.md) 하나로 정리했다. 판단 이유·행동·의사소통의 병렬 구성은 프로브에서 유지하고, 실제로 달라진 ID·동사·결과 계약을 반영했다. 기존 메뉴형·자유서술형은 [날짜별 백업](../backups/prompts/2026-09-10/README.md)에 원본 그대로 보존했다.

자동 접근까지 붙었던 직전 실행 프롬프트는 [legacy-v0.2 보존본](../design/drafts/adventurer_prompt_compose_legacy_v0.2.md)에 고정했다. [최초 개정안 비교](../design/drafts/COMPOSE_PROMPT_COMPARISON_2026-09-10.md)는 당시 프로브의 기록이다.

## 기록 읽기

`run_meta`에는 `action_mode:compose`, `compose_profile:compose-v0.5`(09-11 이전 판은 `compose-v0.4`), `auto_approach:true`, `menu:false`가 남는다. 첫 프로브는 `legacy-v0.1`, 자동 접근만 추가했던 판은 `legacy-v0.2`다.

결정마다 `action_id`, 그 결정에서 발생한 이동과 효과에는 `parent_action_id`가 붙는다. `resolution`에는 원래 행위자·동사·대상과 결과가 남는다. `phase:pending`은 진행 중이고, `phase:resolved`의 `status`는 `success/failed/no_effect`다. 기존 몸 상태 필드 `status`와 충돌하지 않도록 `resolution` 안에 넣었다.

`decisions.input_error_detail`은 거절된 전체 행동과 당시 가능한 ID를 보존한다. 실제 대체 행동은 decisions의 type/target이며 `src:fallback`이다. JSON 불량이면 받은 응답 원문을 남긴다. 로그가 잘린 것과 모델이 존재하지 않는 ID를 쓴 것을 다시 구분할 수 있다.

자세한 계약은 [STREAM_FORMAT.md](../STREAM_FORMAT.md)에 있다. 같은 시드라도 실제 모델 결정은 달라질 수 있다. 결정론 검증은 **같은 시드·같은 입력 결정**에서의 엔진 결과다. 이번 변경의 플레이 효과는 새 원정 로그로 확인한다.

## 검증

- `python verify_action_system.py`: 새 관측·입력·효과, 행동 조합, 물약의 대상별 효과, use/search 접근, then, 길 만료, 장비 교체, 오류 원문 보존.
- `python verify_approach.py`: 거리·사거리·시야·중단·재실행 방지·러너의 건네기/친목 반응 연결.
- `python verify_compose.py`: 구형 외부 호출 호환과 새 프로필의 러너·론처·메뉴형 전환.
- `python verify_reactions.py`: 사건 수신·선택적 평가·잘못된 참조·중복·미평가·집계 비노출·실제 러너 층 왕복과 결산.

모델 호출을 모킹하거나 dummy를 사용하며 실제 LLM 호출은 없다. 테스트 기록은 임시 디렉터리에 쓴다.

직접 실행도 설정이 없으면 compose다. 과거 비교 하니스는 명시적인 `DUNGEON_ACTION_MODE=menu|free` 또는 `DUNGEON_MENU=1|0`으로 백업 지침을 읽을 수 있다. 두 변수가 모두 있으면 `DUNGEON_ACTION_MODE`가 우선한다. 웹 론처의 기본 실행은 부모 프로세스의 구형 설정과 무관하게 compose를 사용한다.
