# 마을 격자 규격 — 맵 제작자에게 (2026-09-11)

**2026-09-11 후속 결정: 저작 원본은 `layout.json`, 아스키는 생성된 검토 출력이다.** 맵 제작자는 막힌 사각형·출입구 칸·출발 칸·던전 입구 칸·NPC id와 칸을 layout에 명시한다. 엔진은 `from_layout`으로 격자를 만들고 `town.json`은 layout을 참조하는 방향이다. 기존 장면·게이트용 `from_ascii`는 유지한다.

정확한 필드와 좌표 이동, 현재 연결 범위는 [마을 1차 layout 계약](../art/town-v1/LAYOUT_CONTRACT.md)을 따른다. `town_layout.compile_layout` 변환과 생성 후보가 준비되어 있고, 엔진 `Dungeon.from_layout`·러너의 `town.json` `{"layout": 상대경로}` 참조 로딩·`check_town.py`의 layout 직접 입력은 **연결됐다**(2026-09-11 밤, verify_town ⑧). 아래 아스키 규격은 **생성 결과의 호환 규격**이다. 현행 `check_town.py`는 생성된 `town-candidate.json`을 받는다.

## 격자 기호

| 기호 | 뜻 | 규칙 |
|---|---|---|
| `#` | 벽(통행 불가) | 건물 발자국·넓은 소품·맵 바깥 테두리 |
| `.` | 바닥 | 잔디·흙·석재 등 걸을 수 있는 칸 전부 |
| `>` | 던전 입구 | **정확히 하나**, 바닥에 놓는다(마을에서는 "던전 입구"로 개명되어 1층 하강) |
| `1`~`9` | 모험가 출발 자리 | 파티 인원(3)만큼은 있어야 한다. 바닥으로 읽힌다 |
| `+` | 문 | **양쪽이 모두 걸을 수 있는 통로**에만(엔진이 문의 두 구역을 계산한다). 실내가 없는 건물 입구에는 쓰지 말고 아래 '문턱' |
| `&` | 그림 표기 | 바닥으로 읽힌다. NPC 자리 표시용 — 실제 NPC는 `npcs` 좌표로 심는다 |

- 바깥 테두리는 한 줄 전부 `#`. 모든 행의 길이가 같아야 한다.
- 크기 제한은 없지만 넓을수록 이동 틱이 늘고(=결정·호출이 늘고) 관측이 커진다. 현행 31×12, 시안 27×20. 40×24 안쪽을 권한다.
- 건물: 엔진에 건물 개념이 아직 없다. 그림 전체가 아니라 **발자국(벽선 위 몇 칸)**만 `#`로 막고, 지붕·처마는 바닥 위에 그리는 것으로 둔다.
  입구는 정면 벽선에 낸 바닥 홈 한 칸(**문턱**) — 실내·포탈은 별도 설계 뒤에 붙는다.
- 소품: 막을 칸만 `#`. 울타리·탁자처럼 넓은 소품은 여러 칸을 막아도 된다(그림 앵커 1칸만 막으면 사람이 그림을 뚫고 걷는다).

## NPC 배치

```json
"npcs": [{"id": "guild_receptionist", "x": 15, "y": 12}]
```

- `id`는 `entities/npc/<id>.json`에 있어야 한다(이름·대사·재방문 대사·선물은 정의가 든다 — [docs/entities.md](entities.md)). 좌표는 바닥 칸.
- 새 NPC(성직자·접수원·주점 주인)의 id는 그림 매니페스트의 행 이름과 맞춘다: `temple_attendant`, `guild_receptionist`, `tavern_keeper`.
  대사·선물 문장은 파트너가 준다. 정의 파일이 없으면 검사기가 막는다.

## 시각 레이어(엔진은 안 읽음)

`town.json`의 `visual` 키에 시안의 `layout.json` 꼴을 그대로 둔다 — `tileSize`, `ground`(바닥 사각형), `guild`/`buildings`(앵커·발 기준), `props`(프레임·발 좌표), `npcs`(행·발 좌표), `manifest`(그림 참조), `offset`(격자에 테두리를 둘렀으면 그 칸 수). 클라이언트(`game/`) 마을 그리기가 이걸 읽는다(후속 작업).

## 검사(0콜)

```powershell
python check_town.py art/town-v1/town-candidate.json   # 후보
python check_town.py town.json                          # 현행
```

테두리·행 길이·`>` 하나·출발 자리·NPC 칸이 바닥인지·NPC id가 정의에 있는지·출발 자리에서 `>`와 모든 NPC까지 길이 이어지는지를 본다.
채택(= `town.json` 교체)은 파트너 확인 뒤 — 그때 `verify_town`·`verify_entities`(마을 NPC 정본 해시)의 기대값을 함께 갱신한다.

## 참고 도구

`art/town-v1/to_ascii.py`는 명시된 layout 필드를 `town_layout.compile_layout`에 전달해 `town-ascii.txt`와 `town-candidate.json`을 만든다. 건물 깊이와 소품 크기를 스크립트 상수로 추측하던 이전 방식은 제거했다.
맵 수정은 layout에서 하고 아스키는 다시 생성한다. 미리보기의 통행 불가 오버레이로 그림과 충돌을 대조한다. 같은 파일에 둬도 잘못 입력한 사각형은 있을 수 있으므로 이 시각 검토가 필요하다.
