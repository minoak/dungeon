# 마을이 '떠나기 전 점검표'로 읽힌다 — 부검과 중앙 광장 구상 (2026-09-17)

> **상태: 논의 기록이다. 결정이 아니다.** 이 문서로 구현된 것은 부검 도구(`tools/town_stay_audit.py`) 하나뿐이다.
> 광장·시계·멀티는 전부 제안이며 6절의 항목을 파트너가 정한 뒤에 설계 번호(D)를 받는다.

## 1. 질문

파트너(09-17): "캐릭터들 행동이 하나같이 바로 던전으로 투입한다는 거야. 뭔가 던전 탐색에 대해서 강하게 목적을 준 거야?"

답: **강하게 준 목적 문장은 없다.** 지침(`prompts/adventurer_prompt.md`)은 오히려 "시트에 목표가 … 없으면 직업을 근거로 목표나 역할을
만들어 붙이지 마라"고 한다. 그런데 캐릭터가 마을에서 읽는 글이 전부 한 방향을 가리킨다(3절).

## 2. 잰 것

마을에서 시작한 실 LLM 판 14개(09-14 ~ 09-17, 전부 유나·미나·수나 파티, gemini_api)의 마을 구간을 0콜로 셌다.
재는 법: 첫 하강(`descend`) 전까지의 `tick.decisions[캐릭터].reason` 문장에 어떤 말이 들어 있나.

| 항목 | 값 |
|---|---|
| 첫 하강까지 마을 체류(내려간 9판) | 41 ~ 145틱 |
| 마을 판단 | 352회 |
| 이유에 던전 준비 말(던전·원정·내려·출발·진입·계단·입구) | 231회 · **66%** |
| 사람·구경만을 이유로 든 판단 | 8회 · **2%** |
| 친목 행동(bond) | 판당 0 ~ 4회 |

체류가 짧은 게 아니다. 머무는 내내 물품 → 의뢰 → 기도 → 동료 모으기 순서로 '떠나기 전 점검표'를 돈다. 표본:

- "원정을 떠나기 전 길드 접수원에게 원정 물품인 물약을 챙기고, 게시판에서 의뢰를 수락하여 준비를 갖추는 것이 효율적이다."
- "노점 상인이 불러 세웠지만 잡동사니 구경 따위엔 관심 없다. 원래 목적지인 길드 접수원에게 가 지원품을 챙겨야 한다."
- 드문 반대 표본: "미나가 칭찬에 수줍어하는 모습이 너무 귀여워! 유나 언니는 아직 멀리 있는 것 같으니까, 미나랑 계속 수다 떨면서 기다려야지☆"
  — 동료를 **기다리는 동안**에만 나온다(기다림이 허락한 틈).

⚠️ 단어 세기라 거칠다. 이유 문장에 그 말이 들어 있나만 보고 뜻은 읽지 않는다. 서로 다른 조건의 판을 비교하는 점수가 아니라,
같은 세계를 고치기 전과 뒤에 같은 잣대를 대 보는 용도다. 표본이 한 파티(유나·미나·수나)뿐이라는 한계도 있다.

## 3. 왜 그렇게 읽히나

1. **지침의 세계 설명 두 줄.** "원정에는 제한 시간이 있다" + "마지막 층에서 내려가면 탈출이다". 시계가 돌고, 끝은 내려가는 것
   하나뿐이다. 그리고 세계가 실제로 그렇다 — 틱 상한(기본 600)은 **마을 틱도 똑같이 깎는다**(`show_runner.py` 의 틱 루프가 하나다).
   서두르는 게 합리적인 세계다.
2. **마을의 모든 말이 던전 준비다.** 접수원 "원정 나가시면 물품 챙겨 가세요" · 성직자 "떠나기 전에 기도하고 가세요" · 떠돌이 모험자
   "던전 내려가나?" · 노점 "던전 잡동사니 있어요" · 주점 주인 "던전 얘기 좀 들려줘". 게시판 의뢰 3건이 전부 던전 일이고,
   건물의 특징 문장도 물품·의뢰·1층 소문이다.
3. **계단 줄이 판단할 때마다 관측 맨 위에 온다.** "함께 내려가려면 …도 곁에 와야 한다".
4. **마을 안내 문단(D81).** 오늘 넣은 것 — 같은 목록을 첫 관측에 한 번 더 읽어 준다.

'규칙으로 강제하지 말고 판단 목록을 넓혀라'는 원칙의 거울상이다: **마을의 판단 목록에 던전 준비가 아닌 항목이 없다.**

## 4. 중앙 광장 구상

파트너(09-17): "중앙 광장에서는 친목 교류가 자주 일어나는 장소로 하자. 여기서 우선은 길드 모집이나 여러 친목 행위를 한다고
하는 거야. 그럼 NPC 들이 여기로 모이겠지." — 09-16 밤의 방향 ⑤(파티 구하기는 캐릭터 자율성 최대, 광장·주점 같은 기본 설정만 주고
어떤 관계를 맺는지 본다)의 연장이다. 모집 메커닉은 아직 없다 — 설정만.

내가 이해한 장면: 마을 한가운데 광장에 파티를 못 구한 견습 모험자와 떠돌이 모험자가 서성인다. 내 캐릭터가 지나가다 말을 섞고,
동료를 거기서 만난다. 던전 준비가 아닌 첫 '할 일'이다.

**지도 사실**
- 광장 구역은 아직 없다. 구역은 여섯(신전 지구·모험가 길드 지구·번화가·주점 지구·샛길·던전 입구 지구).
- 번화가가 십자 모양이다(가로 `[0,15,51,5]` + 세로 `[20,0,5,15]`). 그 **교차점 `[20,15,5,5]`** 가 마을 한가운데이고, 원래 파티 출발
  자리(23,17 등)이고, 바닥도 이미 광장 타일(`plaza_a`)이다.
- 구역 규칙이 단단하다(`town_spaces.resolve`): 구역끼리 겹칠 수 없고, 모든 칸이 구역에 속해야 하고, 구역 사이 연결(`connections`)도
  검증한다. 배치 파일 `art/town-v2/layout.json` 은 지도 트랙의 생성기 `art/town-v2/build_layout.py` 산출물이다.
- '구역 여섯'에 못박힌 곳: `verify_town`(구역 수) · `verify_town_spaces`(구역 수·연결 6) · `verify_guild`(구역 이야기 6·이야기 17벌) ·
  `verify_entities`(map 정의 7) · 마을 정의의 특징 문장 "구역 여섯".
- 마을 사람 지각은 구역 단위다(D70) — 광장을 구역으로 떼면 광장 안 사람끼리만 서로 보이고 들린다.

**제안(추천 순)**
1. **광장 = 교차점 5×5 를 구역으로 떼어낸다.** 번화가 rect 를 셋으로 나누고 연결을 더한다. 구역 정의(특징·이야기 문장은 임시 → 검토표).
   마을 안내 문단에도 한 줄.
2. **모이는 NPC**: 견습 모험자(파티를 구하는 중 — 길드 모집 설정과 맞는다)와 떠돌이 모험자를 광장의 행인으로. 노점 상인은 번화가에.
   2단계 '안 뽑힌 동료 프리셋 = 마을 주민'(D81)도 광장에 세운다.
3. **시간 제한은 첫 하강부터 센다(마을은 시계 밖).** 시계가 그대로면 어울리는 시간이 원정 시간을 깎으므로 광장도 노점 상인처럼 무시될
   가능성이 크다. 파트너의 방향 ④(던전 = 파티가 진입하는 별개의 독립 인스턴스)와도 맞는다. 지침의 "원정에는 제한 시간이 있다"를 어떻게
   바꿀지는 파트너의 문장이다.
4. **NPC 인사에 던전 말이 없는 것을 섞는다** — 검토표 교정 트랙(천천히).

## 5. 여러 사용자가 접속하는 서비스라면

파트너(09-17): "여러 사용자가 접속 가능하게 서비스를 한다고 가정해도 광장을 만들기는 어려울까?"

답: **광장(지도 구역)은 싱글이든 멀티든 같은 작은 일이다.** 어려운 건 광장이 아니라 '한 마을에 여러 사용자가 같이 서 있는 것'이고,
그건 지금 구조와 다른 층의 일이다.

**지금 구조**
- 세계가 계정마다 따로다 — 공개 서버(`server.py`)는 계정마다 러너를 하나씩 띄우고, 그 러너가 자기 마을과 자기 던전을 짓는다(동시 3판 상한).
- 시간이 보조 맞춤(lockstep — 한 틱은 그 판의 모든 캐릭터 판단이 모일 때까지 세계가 기다린다)이다. 판단 하나가 실패하면 세계 전체가
  멈춘다(판단 정지, `brain_pause`). 공유 마을이면 남의 느린 두뇌가 내 시간을 멈춘다.
- 키는 그 사용자의 러너 프로세스 환경에만 있다(D68·D80). 공유 세계를 프로세스 하나로 돌리면 여러 사람의 키가 한곳에 모인다.

**진짜 공유 마을에 필요한 것**
1. 사용자가 들고 나는, 오래 사는 마을 프로세스.
2. 남을 기다리지 않는 비동기 틱 — 생각보다 가깝다. 캐릭터는 이미 사건이 있을 때만 판단하고 나머지는 자동으로 걷는다(실측 ~0.9콜/틱).
3. 키 분리 — 세계 서버는 관측만 보내고 사용자별 두뇌 일꾼이 자기 키로 판단해 돌려준다. 관측·판단이 이미 딕셔너리 계약이라 방향은 맞다.
4. **남이 쓴 글이 내 프롬프트에 들어오는 문제 — 제일 까다롭다.** 다른 사용자의 캐릭터 이름·말·몸짓이 내 관측에 실린다. 프롬프트 인젝션이
   있고, Gemini 차단(D62 — 시트 단어와 몸짓 서술이 겹쳐 터진 그것)이 남의 캐릭터 때문에 내 판에서 터질 수 있다.
5. 광장 인구 상한 — 구역 지각이 있어도 광장에 30명이면 관측이 폭발한다.
6. 관전 방식 — 지금 클라이언트는 판 파일 전체를 1.5초마다 다시 읽는다. 끝없는 마을에는 안 맞는다.

**추천 경로(MVP 먼저)**
1. **싱글 광장** — 4절 그대로.
2. **비동기 멀티** — 다른 사용자가 공개한 저장 캐릭터가 내 마을 광장에 **주민**으로 서 있다. 평소엔 0콜로 걷고, 내 캐릭터가 말을 걸면
   그 사람의 시트로 1콜이 나간다(비용은 말 건 쪽 키). 주인은 나중에 원정 기록에서 '누가 내 캐릭터와 얘기했나'를 본다. D81 2단계
   (안 뽑힌 동료 프리셋 = 마을 주민)와 **같은 배관**이고 주민의 출처만 다른 계정의 캐릭터로 바뀐다. 공유 프로세스·키 섞임·시간 멈춤
   문제가 없다. 남의 글 문제는 남지만 실시간 말·행동이 아니라 고정된 시트 한 장이라 검사 범위가 훨씬 좁다.
3. **진짜 공유 마을 + 인스턴스 던전**(파트너 방향 ④).

갈림: 그리는 그림이 '같은 시간에 같이 있는 것'이면 3번까지, '서로의 캐릭터를 만나는 것'이면 2번으로 충분하다.

## 6. 파트너 결정 대기

- 광장의 자리와 크기(제안: 번화가 교차점 5×5).
- 광장에 세울 NPC(제안: 견습·떠돌이. 노점은 번화가).
- 시간 제한을 마을에도 적용할지(제안: 첫 하강부터 센다) · 지침 문장.
- 멀티의 그림: 같은 시간에 같이 / 서로의 캐릭터를 만남.
- D81 마을 안내 문단을 '동료의 위치' 한 줄로 줄일지(장소 줄은 매 틱 관측과 겹친다).

## 7. 다시 재는 법

```
python tools/town_stay_audit.py            # runs/ 의 최근 14판 + state/stream.jsonl
python tools/town_stay_audit.py --show 12  # 판마다 마을 판단 이유를 앞에서 12개씩
```

기준선(09-17): 마을 판단 352회 · 던전 준비 말 66% · 사람·구경 말만 2%. 광장·시계를 넣은 뒤 실판으로 다시 잰다 — 캐릭터가 광장에
머무는지는 시간축에서만 보이는 일이라 풀판 사유가 된다(마을 구간 ≈ 40~50콜, 돌리기 전에 콜 수를 먼저 말한다).
