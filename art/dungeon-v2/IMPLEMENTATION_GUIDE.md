# 던전 환경 구현 지시서

기준일: 2026-09-20. 기준 이미지: `concept.png`.

## 목표와 현재 구현

목표는 최초 시안의 재질, 공간 비율, 석조 건축의 두께와 빛을 무작위 시드에서도 유지하는 것이다.
방 수·위치·크기와 연결 관계는 시드마다 달라진다. 시안의 재질과 건축 비율을 유지하면서 큰 홀·회랑·작은 방을 조합하고, 렌더러가 벽 높이와 작은 디테일을 부여한다.

현재 비교 페이지의 기본값은 새 생성 규칙 `concept`과 입체 렌더러다. 엔진의 Dungeon을 상속하여 실제 격자, 출구, 몬스터, 함정, 시야를 만든다. 기존 생성기는 메뉴에서 선택할 수 있다. 일반 러너의 기본 생성 방식은 아직 이 프로필로 전환하지 않았다.

## 생성 순서와 공간 규칙

1. 42×34 격자에 5–8개 방을 배치한다. 고정 섹터·중앙 방·대칭 구도를 두지 않고 방 사이에는 최소 2칸 간격을 확보한다.
2. 대홀 후보는 0/1/2개를 3:6:1 가중치로 선택한다. 대홀은 12–15×9–11칸, 일반 방은 6–10×5–8칸, 회랑은 10–13×4–5칸이며 회랑 방향도 바뀐다. 공간이 부족하면 배치를 재시도하고 최소 5개 방을 보장한다.
3. 거리 가중치를 무작위로 흔든 최소 신장 트리로 모든 방을 연결하고 짧은 우회 연결을 0–2개 추가한다. 통로 폭은 2–3칸이며 다른 방을 가로지르는 횟수가 적은 꺾임 방향을 선택한다.
4. 방의 약 20%는 열린 입구를 유지한다. 나머지는 적합한 2–3칸 문턱을 한 칸 문과 석벽으로 좁히되 전체 보행 연결을 끊으면 되돌린다.
5. 대홀은 열린 홀 또는 네 기둥 홀로 선택한다. 충분히 큰 일반 방에는 쌍기둥 방도 생긴다. 기둥은 실제 벽 칸이며, 전체 보행 연결을 유지할 때만 채택한다. 통로·문턱 교차에서 우연히 생긴 독립 벽 한 칸은 제거한다.
6. 지형이 확정된 뒤 엔진이 피처·몬스터·함정을 배치한다. 시각 부품의 난수는 별도 좌표 해시로 계산하며 엔진 RNG를 소비하지 않는다.

같은 시드는 같은 지형과 같은 소품 배치를 만든다. 네 기둥 홀은 선택 가능한 방 유형이며 매번 등장하지 않는다. 스냅샷의 `architecture.version=2`와 방별 `art_style`에 생성 결과를 기록한다.

## 재질과 건축 부품 계약

| 항목 | 규칙 |
| --- | --- |
| 이동 격자 | 48px. 돌 무늬의 크기와 이동 칸의 크기를 분리한다. |
| 바닥 | 시안에서 추출한 작은 불규칙 판석. 반사 반복 패턴으로 경계가 이어지게 한다. |
| 벽 | 80px 높이, 돌출된 상단석과 하단 받침. 정면·측면·끝·모서리를 이웃 칸으로 판정한다. |
| 독립 기둥 | 96px 부품, 실제 `#` 칸에만 배치. 푸른 깃발과 옆 횃불을 부착한다. |
| 벽 부착 기둥 | 연속된 정면 벽 9칸 이상에만 배치. 양 끝에 일반 벽 4칸 이상, 기둥 간 8칸 간격. 폭 26px·높이 80px로 독립 기둥보다 작게 만든다. |
| 문 | 정면/측면 전용 부품. `+` 칸의 통로 방향으로 선택하며 벽과 같은 발 위치 정렬을 쓴다. |
| 새 부품 시트 | 셀 128px, 발 앵커 120px. 알파 바깥 RGB는 투명 영역으로 취급한다. |
| 기존 소품 시트 | 셀 96px, 발 앵커 92px. |
| 빛 | 차가운 바탕색과 국소적인 주황빛. 벽 조명은 세계 좌표를 기준으로 이어지고 바닥 빛은 벽/문을 통과하지 않는다. |
| 외곽 | 바깥 암반 칸에 낮은 돌무더기를 배치한다. 방 바닥을 덮지 않으며 소유 벽의 발견 상태를 따른다. |

구조물의 높이를 타일 안에 억지로 압축하지 않는다. 접지점의 Y로 캐릭터와 구조물을 함께 정렬한다. 보이는 캐릭터가 벽 뒤에 들어가면 해당 벽·부착물만 28%로 옅어지고, 앞으로 나오면 원래 밝기로 복구한다. 미발견 구조물은 숨기고, 기억한 구조물은 45% 밝기로 남긴다. 지형 안개는 바닥을 담당하고 높이 있는 부품은 각자 가시성을 담당한다.

## 소품 배치

- 통·상자·항아리·큰 잔해는 방 가장자리의 바닥에 놓는다. 작은 방은 한 모서리, 큰 방은 대각선의 두 모서리에 모은다.
- 작은 방은 최대 4개, 큰 방은 면적의 약 10%와 12개 중 작은 수를 상한으로 한다. 큰 방에서는 모서리 가까운 두 번째 줄도 사용한다.
- 문과 그 주변 8칸, 열린 통로 입구, 피처·계단의 인접 칸, 초기 캐릭터·몬스터 주변, 함정 칸을 비운다.
- 후보를 하나 채택할 때마다 누적 소품 칸을 막았다고 가정하여 나머지 모든 바닥이 연결되는지 확인한다.
- 깃발·거미줄·담쟁이는 벽 부착물이다. 작은 이끼와 납작한 돌 조각은 바닥 데칼이다. 낮은 디테일과 큰 장애물의 역할을 섞지 않는다.

현재 통·상자·항아리·잔해는 시각 소품이며 밀기·파괴·충돌이 없다. 이는 실제 기둥의 충돌과 다르다. 이동하는 본편에 적용할 때 큰 소품을 단순 이미지로 남겨 캐릭터가 통과하는 상태를 완성으로 취급하지 않는다.

## 본편 통합 순서

1. 새 생성기를 러너가 명시적으로 선택할 수 있는 프로필로 연결한다. 격자 크기와 생성 버전을 run 메타데이터에 기록한다. 저장된 판을 현재 생성 규칙으로 다시 생성하지 않는다.
2. 큰 소품 배치를 엔진 소유의 구조화된 데이터로 옮긴다. `id`, 종류, 위치, 차지하는 칸, 통행 차단 여부를 스트림에 기록한다. 클라이언트가 충돌 배치를 독자적으로 재추첨하지 않도록 한다.
3. 먼저 고정 장애물을 적용한다. 출입구·계단·상자 접근과 모든 보행 칸의 연결을 유지하고, 캐릭터/몬스터의 경로 탐색과 실제 한 칸 이동이 같은 규칙을 사용하게 한다.
4. 밀기나 파괴는 별도 상호작용으로 추가할 수 있다. 물건이 이동한 뒤 길막힘·점유 충돌·저장/재개를 검증한다. 그 기능이 필요하지 않은 작은 잔해는 비충돌 데칼로 유지한다.
5. 장식 밀도, 조명, 오브젝트 크기를 현재 비교 페이지와 대조한다. 본편으로 옮기면서 다시 작은 방과 얇은 벽으로 돌아가지 않는다.

던전 입장, 파티 결성, 탐험 목표는 이 생성 규칙이 결정하지 않는다. 이 작업은 공간과 표현을 정의하며 캐릭터를 연기하는 에이전트의 결정을 대체하지 않는다.

## 검증 기준

실행 명령과 결과 파일은 README에 정리되어 있다. 기존 생성기 100개·새 생성기 1,000개 시드를 검사하고, 장식·벽 계획은 프로필별 100개씩 검사한다. 새 문턱·기둥 규칙을 바꿀 때는 방 겹침, 격자 경계, 방 연결 그래프, 모든 바닥의 연결, 출구 접근, 기둥의 실제 충돌과 부착 기둥 간격을 다시 확인한다.

브라우저에서는 같은 시드로 프로필을 왕복하고 지형 이미지와 동적 텍스처가 누적되지 않는지 확인한다. 같은 격자·카메라로 이전 그림과 비교한다. 벽 뒤/앞의 캐릭터, 미발견 계단, 기억한 벽, 문 방향, 그림자와 장식 누출을 확인한다.

현재 검증은 LLM 0콜의 지형·렌더러 검증이다. 실제 장시간 자율 탐험, 소품 충돌, 밀기, 파괴는 검증했다고 주장하지 않는다.
