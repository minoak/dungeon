# 원더랜드 마을 v3

2026-09-19. 승인한 `art/town-v3-draft` 배치를 실제 엔티티·스프라이트·게임 화면에 연결했다. `town.json`이 이 폴더의 `layout.json`을 읽는다. 새 원정부터 적용되며 진행 중인 판이나 저장된 기록의 지도를 갈아 끼우지 않는다.

## 조감도에 맞춘 조경 보강

처음 조감도의 수목·담장·화단·시장 밀도를 반영했다. 나무·관목·꽃상자·돌담·울타리·암벽·분수·깃발 가로등·큰 노점·조각상·화물 수레·계단 16종의 에셋으로 장식 184개를 추가했다. 기존 건물 14채와 구역 경계는 유지한다. 중앙은 돌바닥 시장, 신전은 정원, 주거구역은 작은 마당과 골목, 던전 입구는 암벽 숲으로 꾸몄다.

나무는 줄기, 담장·분수·암벽은 바닥 점유 영역에 충돌이 있다. 계단 그림은 평지의 보행 장식이며 높이 시스템을 추가하지 않는다. 실제 통행을 끊거나 문턱·NPC·기존 상호작용 접근 칸을 막는 후보는 배치하지 않는다. `landscaping.json`에 배치와 제외 결과를 남긴다.

`layout-base.json`이 조경 전 배치 정본이며 `decorate.py`가 그 위에 조경을 추가해 실행용 `layout.json`을 만든다. 건물 배치를 수정할 때는 base를, 조경을 수정할 때는 decorate를 고친다.

## 길 포장 보강

큰길·신전·길드 앞은 밝은 판석, 시장은 헤링본 벽돌, 주거 골목·상점 작업장은 자갈돌, 던전 입구는 이끼 낀 석재를 사용한다. 생성한 재질 8개를 2×2칸 무늬로 나누어 이음새를 유지한다. 1,527칸의 표면과 경계석 689개 구간, 배수구 11곳, 광장 문양 3곳을 그린다. 모든 장식은 바닥 레이어에 있고 통행·충돌·구역은 바꾸지 않는다.

`pack-paving.mjs`는 옛 지형 프레임 0–7을 보존하고 32프레임을 추가한다. `pave.py`는 길의 재질과 장식 정보를 만든다. `pack.mjs`와 `decorate.py`가 각각 이 단계를 자동 실행한다. `layout.json`의 `ground.frame`과 `paving`은 시각 정보이며, 게임의 `townPaving.ts`와 제작용 미리보기가 같은 배치 정보를 읽는다.

## 공간

내부 64×48칸, 테두리 포함 66×50칸. 바닥 2,052칸 전체가 연결되며 모든 내부 칸은 정확히 한 구역에 속한다.

| 구역 | 시설 |
|---|---|
| `main_street` 번화가 | 주점·잡화점·시장 노점·야외 식탁·서쪽 외부 출구 예정지 |
| `shop_district` 상점가 | 대장간·공방·장비점·모루·작업대·장비 거치대 |
| `residential_district` 주거구역 | 주민의 집 3채·공동 숙소·일반 여관·정원 숙소·우물·빨랫줄 |
| `temple_district` 신전 지구 | 신전·추모비·벤치 |
| `guild_district` 모험가 길드 지구 | 길드·게시판·앞마당·벤치 |
| `dungeon_district` 던전 입구 지구 | 던전 입구·출발 마당·보급 상자 |

건물 14채(12종)와 향후 상호작용을 위한 소품 15곳이다. 새 시설은 문턱·소개·이야기만 제공한다. 거래·제작·강화·숙박 비용과 효과는 구현하지 않았다. 소품은 그림과 충돌만 있으며 아직 행동 대상으로 관측되지 않는다. `design-objects.json`에 각각의 접근 칸과 예정 용도를 기록했다.

길드와 주점이 놓인 **길드 구역과 번화가 전체**가 기존 파티 결성 장소가 된다. `guild_district`, `main_street`와 행인 세 명의 정의·보행 범위를 유지했다. 던전 출구 피처는 하나이며 3명 파티 규칙은 기존 엔진이 담당한다. 마을 밖은 닫힌 서쪽 표식만 있고 다른 맵으로 넘어가지 않는다.

기존 흩어진 출발의 건물 선택 순서를 유지하도록 새 건물 인스턴스 id에 `z_` 접두사를 붙였다. 기본 출발점은 번화가이며, 흩어진 출발은 길드·주점·신전 앞이다.

## 보기와 수정

- `preview.html`: 이미지가 내장된 단일 파일. 건물·소품 선택, 구역·격자·충돌, 31개 목적지 경로, PNG 저장.
- `game-overview.png`: 실제 게임 클라이언트의 전체 지도. `game-preview.png`는 캐릭터 시점.
- `layout-base.json` + `decorate.py`: 배치 정본. `layout.json`은 생성 결과다. 건물 크기·문턱·이야기는 저장소 `entities/`의 정의를 사용한다.
- `source/`: 생성한 건물 8종·소품 12종·조경 16종·포장 재질 8종 원본 아틀라스. `pack.mjs`가 투명 여백을 기준으로 분리하고 `runtime/` 및 게임 에셋으로 내보낸다. 기존 소품 프레임 0–19를 보존하고 조경 프레임 20–35를 뒤에 붙인다(`pack-details.mjs`).
- `compiled.json`, `town-ascii.txt`, `validation.json`: 정본으로부터 만든 검토 자료. 직접 수정하지 않는다.

저장소 루트에서 실행한다.

```powershell
node art/town-v3/pack.mjs
python art/town-v3/decorate.py
python verify_town_v3.py --export
python art/town-v3/export.py
node art/town-v3/verify_preview.mjs
python art/town-v3/engine_preview.py
node art/town-v3/verify-game.mjs
python art/town-v3/verify_isolated.py --all
```

이미지를 바꾸지 않았다면 `pack.mjs`는 생략한다. 브라우저 검사는 로컬 Edge와 game의 Node 의존성을 사용한다. `verify-game.mjs`는 합성 스냅샷과 기존 공개 데모 기록만 재생한다. 실제 LLM 호출은 없다.

`verify_isolated.py`는 소스 복사본을 임시 폴더에 만들어 기존 회귀 게이트를 실행한다. 실제 `state/`, `.env`와 개인 판 기록을 복사하거나 덮어쓰지 않는다. 검증 로그는 로컬 전용 `state_map_v3_checks/`에 둔다.
