# 서브컬처 SD 도트 · 1차 적용본

2026-09-09. 사용자 방향: 특정 캐릭터보다 서브컬처 그림체, 큰 눈의 SD 비율, 도트 질감 유지.

## 결과와 적용

- 검사 헤어 5종 + 궁수·도적 헤어 각 3종 = 11가지 외형 × 정면/오른쪽/뒷면/왼쪽 × 정지 1 + 걷기 4 = 총 220프레임.
- 런타임: `../../viewer/assets/sprites/sd/`의 기본 시트 3장과 헤어별 추가 시트 8장, `atlas.json`.
- 각 칸 96×96, 시트 480×384, 투명 PNG. 알파 0/255, 발 바닥 y=91, 사방 여백.
- 이 크기는 **게임용 출력 캔버스 규격**이다. 생성 원본을 정확한 32×48 논리 픽셀로 저작했다는 뜻은 아니다.
- 론처의 새 커스텀 파티는 처음에 SD 외형으로 표시한다. 외형 메뉴에서 세 종류 또는 기존 파츠 조합을 고른다.
- SD 외형을 고른 뒤 **헤어스타일**을 선택한다. 머리색·의상 색 변경은 아직 지원하지 않는다. 파츠 조합으로 전환하면 기존 머리·몸통·색 편집을 쓴다.
- 검사: 헝클어진 머리 / 가르마 / 반묶음 / **긴 머리 / 양갈래**. 궁수: 포니테일 / 단발 / 땋은 머리. 도적: 단발+옆땋기 / 숏컷 / 포니테일.
- 긴 머리(`long`)·양갈래(`twintails`)는 같은 검사의 얼굴·의상에서 여성적인 인상을 헤어만으로 표현해 보려는 추가 작업이다. 성별 선택과 헤어 선택은 독립적이며 어느 성별에서도 고를 수 있다. 현재 이 두 시트는 검사 의상용이다.
- `look.sprite`에 외형 id, `look.hairstyle`에 선택한 머리를 저장한다. 기존 `look.head/body/colors`는 보존하며, SD 파일을 못 읽으면 그 파츠로 대체 표시한다.
- `hairstyle`이 없는 기존 SD 저장본은 기본 머리로 표시한다. 머리 파일만 실패하면 그 외형의 기본 머리로 표시한다. 외형을 바꾸면 헤어 선택은 새 외형의 기본값으로 초기화한다.
- 외형 선택은 직업·성별·능력치를 바꾸지 않는다. 기존 판과 기본 파티의 랜덤 외형은 자동 교체하지 않는다.
- 관전 화면은 SD를 타일의 1.5배 크기로 발 위치에 맞춰 그리고, 번호를 머리 위에 표시한다. 파티 패널 64px 초상화, 지도 `가까이 보기` 추가.
- 단일 파일 `replay_viewer.html` 생성기는 별도 구현이므로 이 변경의 적용 대상이 아니다. 웹 관전 뷰어에 적용했다.

일반 게임은 기존 `wonderland.bat` / `launcher.py`를 사용한다. 이미 실행 중이던 론처는 새 외형 사전을 읽도록 다시 시작해야 한다.

## 임시 HTML 뷰어와 다음 뷰어의 연동

사용자 방침(2026-09-09): **현재 HTML 뷰어는 임시이며 교체할 예정**이다. 이번 작업의 중심은 캐릭터 에셋 추가이며, 뷰어의 기능 확장을 전제로 에셋을 설계하지 않는다.

다음 뷰어는 `viewer/assets/sprites/sd/`의 PNG와 `atlas.json`을 함께 가져오면 된다. 이 폴더의 현재 위치는 배포 경로이며, 그림과 목록 형식은 HTML·Canvas 코드에 의존하지 않는다. `sprites.js`는 현재 웹 화면의 표시 구현이므로 새 뷰어에서 반드시 재사용할 필요가 없다.

| 항목 | 읽는 방법 |
| --- | --- |
| 선택값 | `look.sprite`로 `presets` 항목을 찾고 `look.hairstyle`로 그 안의 `hairstyles` 항목을 찾는다. 예: `sd-warrior` + `long`. |
| 그림 경로 | 선택한 헤어의 `sheet`를 `atlas.json`이 있는 폴더 기준으로 연다. 헤어가 없거나 불러오기에 실패하면 해당 외형의 기본 `sheet`를 쓴다. |
| 프레임 영역 | `cell` = 96. 행은 `directions` 순서, 열은 정지 0 / 걷기 1~4. 좌측 상단에서 x = 열 × 96, y = 행 × 96으로 자른다. |
| 표시 | 투명 배경을 보존하고, 도트가 흐려지지 않는 최근접 보간으로 확대·축소한다. 현재 발 바닥은 셀 안의 y=91이다. |
| 애니메이션 | 현재 걷기 기본 간격 `frame_ms` = 160ms. `display_scale` = 1.5는 현재 뷰어의 타일 대비 크기이며, 새 뷰어에서는 화면 규격에 맞춰 정한다. |
| 저장·판정 | `look.sprite` / `look.hairstyle`은 저장과 리플레이에 그대로 전달한다. 직업·성별·능력치와 독립적인 외형 값이다. |

머리별 PNG는 **전체 캐릭터 프레임**이다. 다른 의상에 같은 PNG를 붙이면 의상까지 바뀌므로, 독립 헤어 레이어로 취급하면 안 된다. 기존 선택 id는 계속 유지한다.

## 제작 방식과 원본

모든 새 그림은 **내장 image_gen**으로 제작했다. CLI/API 대체 경로를 쓰지 않았다.

- `sd-*-source.png`: 3종 생성 원본, 수정 없이 보존. 배경은 크로마키용 분홍색.
- `sd-*-prompt.txt`: 실제 최종 생성 프롬프트. 전사 시트를 궁수·도적의 그림체와 배치 참고로 사용.
- `hairstyles/*-source.png`, `hairstyles/*-prompt.txt`: 기본 시트를 내장 image_gen으로 편집해 만든 추가 헤어 8종의 원본과 실제 프롬프트. 이번 추가분은 `warrior-long-*`, `warrior-twintails-*`다.
- `warrior-pixel-study*`: 방향 확인 전에 만든 점눈 전사 연구. 최종 세트에 미적용.
- `anime-style-study*`: 애니메이션풍 얼굴·의상 참고. 매끈한 그림체 자체는 최종 세트에 미적용.
- `build-runtime.mjs`: 분홍 배경 제거, 경계 혼색 중화, 빈 공간 기준 행/열 분리, 머리 중심·발 위치 정렬, 동일 배율로 축소 후 PNG 출력.
- `build-report.json`: 원본 영역·정렬 기준·출력 영역 기록.

헤어는 별도 선택값으로 관리하되 렌더링은 **머리별로 준비한 전체 프레임**을 사용한다. 실시간으로 가발 레이어를 합성하는 구조는 아니다. 긴 머리가 가렸던 망토·화살통을 복원하고 네 방향의 결합부를 이미지에서 검토하기 위해 이 방식을 사용했다. 출력 배율과 머리 중심은 기본 외형을 기준으로 고정해서, 머리 길이가 달라져도 몸이 커지거나 옆으로 밀리지 않게 했다. 원본 얼굴·의상을 유지하도록 편집했지만 생성 편집이므로 픽셀 단위의 완전 동일성을 보장하지는 않는다.

재생성: `node art/sprites-v4/build-runtime.mjs`. Node와 Playwright 필요. Windows에서는 설치된 Edge를 사용하며, `playwright` 패키지 또는 Codex 번들 런타임 경로를 찾는다.

## 검증과 미술상 한계

통과: `python verify_sd_assets.py --demo`, `python verify_launcher.py`, 검토 서버 실행 후 `node art/sprites-v4/verify-browser.mjs`.

외형·머리 id 검증·저장·run_meta 전달, 잘못된 조합 거부, 같은 시드에서 머리 변경 전후 위치/HP/행동 일치, 220프레임 알파·잘림·발 바닥, 11가지 머리 표시·캐시 분리, 방향/프레임 선택, 모바일 갤러리 너비, 론처 머리/파츠 전환·저장, 실제 관전 재생, PNG/머리 파일 실패 시 대체 표시, JS 오류 없음 확인.
`hairstyles/gallery-preview.png`, `hairstyles/selection-preview.png`, `hairstyles/launcher-preview.png`, `hairstyles/viewer-preview.png`는 헤어 선택을 적용한 실제 브라우저 화면이다. 최상위의 같은 이름 이미지는 이전 기본 외형 적용 화면이다.
`hairstyles/warrior-comparison-preview.png`는 같은 검사에 기본 머리·긴 머리·양갈래를 적용한 비교 화면이다. 기존 갤러리의 검토 화면에서 세 카드를 같은 검사로 맞춰 캡처했으며, 별도 뷰어 기능을 추가하지 않았다.

**기술 검증 통과는 미술 완성 판정이 아니다.** 생성 프레임에는 비슷한 발 자세가 반복되고 방향별 망토·무기·땋은 머리 표현이 조금 달라진다. 걷기의 정확한 좌우 발 교차, 장비를 든 손의 방향별 가림, 가장자리 픽셀 정돈은 추가 개선 대상이다. 현재 결과는 스타일을 게임 안에서 검토할 수 있는 첫 적용본이다.
