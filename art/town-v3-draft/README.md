# 원더랜드 마을 v3 — 지도 설계 초안

2026-09-19. **실행 맵에 연결하지 않은 독립 초안**이다. `town.json`, `art/town-v2/`, 실제 `entities/`, 엔진·론처·게이트 목록을 수정하지 않는다. Claude Code의 동시 작업과 분리한다. 생산·강화 구현은 이번 범위에서 제외한다.

## 보기

- `preview.html`: 이미지·데이터를 내장한 단일 HTML. 브라우저에서 파일을 직접 열 수 있다. 구역·격자·충돌 표시, 건물/오브젝트 선택, 경로 확인, PNG 저장 지원.
- `map-overview.png`: 데이터로 렌더링한 배치도. 기존 필수 건물 4종은 기존 그림을 사용하고, 새 건물은 도형으로 만든 임시 외형이다. 최종 픽셀 아트가 아니다.
- `map-contract.png`: 같은 지도 위에 구역·충돌·격자를 겹친 검토용 지도.
- `concept-reference.png`: 앞서 생성한 분위기 참고 시안. 좌표·구역·충돌의 정본이 아니며, 그 이미지의 북쪽/남쪽 출구와 수로를 구현하지 않는다.

## 배치

내부 64×48칸(테두리 포함 66×50). 기존 51×37보다 시설과 마당을 담을 공간을 늘린 **크기 제안**이다. 실제 판단 비용·이동 시간 영향은 미측정이다. 모든 바닥뿐 아니라 내부의 모든 칸에 구역 하나를 할당한다.

| 구역 ID | 이름 | 배치 내용 |
|---|---|---|
| `temple_district` | 신전 구역 | 신전·정원·추모비·벤치 |
| `guild_district` | 모험가 길드 구역 | 길드·앞마당·게시판·벤치 |
| `main_street` | 번화가 | 시장·잡화점·주점·서쪽 출구 예정지 |
| `shop_district` | 상점가 | 대장간·공방·장비점·작업 마당 |
| `residential_district` | 주거구역 | 주민의 집·공동 숙소·일반 여관·정원 숙소·공동 우물 |
| `dungeon_district` | 던전 입구 구역 | 던전 입구·출발 마당 |

주점을 번화가에 두는 것은 시안상의 제안이다. 건물로 파티 결성 구역을 찾는 현재 계약에 따라 **번화가 전체와 길드 구역 전체**가 결성 장소가 된다. 숙박 등급은 공간·외형의 제안만 있으며 가격·재산·숙박 효과는 정하지 않았다.

## 지키는 계약

1. 구역에 `id`, `name`, `rects`, 엔티티 참조가 있다. 초안 전용 `entities/map/`에 6개 구역과 마을 정의가 있으며 특징·이야기 문구도 있다. 해당 문구는 프롬프트에 들어갈 초안이므로 통합 전에 검토한다.
2. `guild_hall`과 `tavern`을 각각 `guild_district`, `main_street`에 놓았다. 건물 전체 점유 영역이 소속 구역 안에 있다.
3. `dungeon_gate` 정의와 `dungeon_entry` 하나가 있다. 건물 문턱 바로 앞의 출구 피처는 정확히 하나다. 3명 파티 규칙과 입구 문구 교체는 기존 러너·엔진의 책임이며 이 초안에 중복 구현하지 않는다.
4. `guild_district`와 `main_street` ID를 유지한다. 견습·떠돌이 모험자의 `walk.rect=[29,11,17,4]`도 그대로 길드 앞마당에 남긴다. 실제 NPC 정의는 수정하지 않는다. 세 행인의 걸을 수 있는 후보 칸을 검증한다.
5. 모든 건물은 엔티티로 연결된다. 새 건물 정의는 이 폴더의 `entities/building/`에만 있다. 기존 건물 4종은 작성 시점의 정의를 복사한 것이므로 통합 시 최신 본체 정의와 비교해야 한다.
6. 모루·작업대 등 15개는 `design-objects.json`의 **배치 후보**다. 각각 소속 구역, 점유 칸, 옆의 접근 칸, 향후 용도가 있다. 해당 칸의 충돌만 초안 지도에 반영했으며 실제 `Feature`나 행동을 등록하지 않았다.
7. 마을 밖은 `(0,27)`의 서쪽 예약 표식 하나다. 경계는 닫혀 있고 바깥 맵·전이·두 번째 출구 피처를 만들지 않는다.

## 재생성과 검증

저장소 루트에서:

```powershell
python art/town-v3-draft/build_draft.py
node art/town-v3-draft/verify_preview.mjs
```

`build_draft.py`는 현재 저장소의 정의를 읽고 이 폴더 안에만 결과를 쓴다. 배치 수정은 이 스크립트에서 수행한 뒤 재생성한다. `layout.json`을 직접 수정하면 재생성 시 덮어쓴다. 기존 `town_spaces.resolve`에 초안 정의를 명시적으로 넘기고, 기존 `town_layout.compile_layout`으로 검증한다. 전역 엔티티 캐시나 게임을 변경하지 않는다.

`validation.json`에 내부/바닥 칸 수, 빈틈·중복, 모든 바닥의 연결, 필수 건물, 단일 던전 출구, 오브젝트 접근, 행인 후보 칸, 사용한 계약 소스 SHA-256을 기록한다. `browser-validation.json`은 31개 목적지 경로·토글·클릭·390px 화면·브라우저 오류를 기록한다. 게임 실행과 LLM 호출은 없다.

## 통합은 다음 작업

이 폴더를 그대로 실행 맵으로 연결하면 안 된다. 새 건물 `draft_*` 텍스처는 초안 미리보기의 임시 도형이다. 실제 스프라이트 제작, 필요한 정의만 본체로 병합, 새 구역·주점 위치에 따른 관측/말/결성 검증, NPC 외형과 보행 확인, 런타임 지도 연결은 별도 작업이다. 기존 정의 사본을 일괄 복사하여 다른 세션의 변경을 덮어쓰지 않는다. 생산·강화·숙박·경제 규칙 역시 이번 초안으로 확정하지 않는다.
