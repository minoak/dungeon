## 한 줄 재정의

검증 질문: LLM 에이전트가 닫힌 세계에서 볼 만한 모험(탐험·전투·상호작용)을 살 수 있는가.

## 확정된 결정들

### 1. GM 제거 (구조 변경 중 최대)
GM의 세 역할을 분해해서 각각 다른 곳으로 보낸다:
- **심판** → 세계의 물리로 흡수. 사라지는 게 아니라 더 커짐(픽셀 던전 규칙 소유).
- **자유행동 판정** → 규칙의 두께가 대체. 규칙이 촘촘하면 판정할 자유행동이 없다.
  대가: 에이전트는 규칙에 있는 동사만 쓴다. TRPG가 아니라 MMO다. 의도된 장르 선택.
- **서사** → 세계의 기관에서 "온디맨드 렌더링"으로 강등. 원하는 유저가
  자기 키로 자기 캐릭터 로그를 산문으로 굽는 선택 기능. 기본값은 로그.
- 부수 효과: 시스템의 **모든 LLM 호출이 BYOK**가 됨. 운영자 지능 비용 소멸.

### 2. 픽셀 던전 규칙 차용 (전투·세계 물리)
규칙은 발명하지 않고 사 온다. 10년 검증된 밸런스.
- **가져올 것 (세계의 물리)**: 에너지 기반 타임라인(행동 비용만큼 다음 턴이 밀림 —
  LLM 호출 지연이 버그가 아니라 게임 속성이 됨), 감산 방어, 점근적 명중식,
  포만도(허기 = 뭉개기 방지 소프트 타이머 + 상충 욕구의 첫 축), 시야/기습.
- **버릴 것 (인간 플레이어의 빌드 게임)**: 클래스/서브클래스/특성 트리(페르소나가
  그 자리), 미확인 아이템 감정(에이전트에겐 obs 노이즈), 인벤토리 퍼즐.
- **라이선스**: 코드 이식 금지(GPLv3 전염). 규칙·산술식만 파이썬 재구현. 메커니즘은
  저작권 대상 아님.
- 차용도 지금은 얇게: 검증 실험에 필요한 조각만 먼저.

### 3. 판단 아키텍처 (도주버튼 논의의 결론)
- 판단을 선점하는 자동 규칙(HP 임계 자동도주 등) 금지. 캐릭터성이 죽는 지점.
- **상태 전이 시에만 심의 승격**: 첫 피격, HP 50%/25% 선 통과, 새 적 조우.
  내린 판단("싸운다")은 다음 전이까지 반사(코드)가 집행. 호출 밀도 = 전투당 2~3회.
- 도주는 fallback_policy에도 존재: 두뇌 부재(키 소진/타임아웃) 시 기본 행동.
  심의 선점이면 과설계, 폴백 서랍이면 필수 부품.
- 요약: **방향은 전부 에이전트, 집행은 전부 코드.**

### 4. 제품의 본체 = 구조화된 로그
GM 산문의 대체재. 관전물의 장르 문법(DF 전설 모드, EVE 킬메일).
- **사건의 구조**: 문자열 로그가 아니라 이벤트(누가/무엇을/누구에게/결과/틱).
  픽셀 던전의 결정론 판정이 이벤트 스키마를 공짜로 줌. append-only 원장과 동일 계보.
- **목소리**: 봇의 reason 필드가 제품에서 가장 중요한 텍스트로 승격.
  페르소나 프롬프트가 reason의 톤까지 지배하게 할 것.
- **초점**: 캐릭터 단위 필터, 사건 등급(전투/조우/발견 굵게, 이동 흐리게).
- 이 로그 작업은 서비스 선행 개발이 아니라 **검증 실험의 계측기 제작**. 작업이 겹침.

### 5. 렌더링 — ASCII는 화면 뒤로, 판정은 영원히 그리드
- 진실은 문자 그리드 유지. 뷰어만 문자→스프라이트 치환(NetHack 타일 모드 방식).
- 3단계: ① ASCII 그대로(현재) → ② 좌표 유지 타일 치환(셀=스프라이트 슬롯,
  좌표 변환 없음, 하루짜리) → ③ 보간 애니메이션·방향 스프라이트·시야 안개까지.
- 경계선: **픽셀은 보간까지, 판정은 그리드.** 픽셀 단위 자유 이동/물리 금지 —
  그리드가 진실이길 그만두는 순간 심판·시야·obs 전부 재설계됨.
- 봇의 obs는 영원히 텍스트. 픽셀은 인간용.
- ②단계 + SSE 뷰어 = 커뮤니티에 보여줄 수 있는 화면. 이미지 문제 80% 해결 지점.
- CC0 타일셋(Kenney, 던전 크롤 계열) 사용. 그림 그리지 말 것.

### 6. tmux 폐기 — 레이어 5 재정의
- 구 레이어 5(tmux 4분할)는 학습 목표였고, 배포 전제에서는 버려지는 실습.
- 신 레이어 5: **월드 루프 단일 데몬 + SQLite + FastAPI SSE 웹 뷰어.**
  검증 비용은 tmux와 비슷한데 결과물이 소프트 런치의 뼈대.
- 뷰어 렌더링 라이브러리로 PixiJS/Phaser는 허용(엔진 채택 아니고 그리기 층).
- 게임 엔진(유니티/Godot) 불채택 확정: 원더랜드의 어려운 문제(에이전트 하네스,
  서버 소유 세계)를 하나도 안 풀어줌. 서버 진실 + 브라우저 창 구조가 정석.

### 7. 두뇌 교체 — CLI에서 HTTP API로
- Claude Code 헤들리스 CLI(~20s Node 부팅)를 HTTP API 호출로 교체.
- 최종 BYOK 구조와 동형이라 반걸음 전진. brain 인터페이스 그대로, 새 brain 모듈 하나.
- 코파일럿 API 사용 시: 공식 GitHub Models(무료·rate limit 빡빡) vs 프록시(ToS 회색)
  구분할 것. 안정성 판정 기준에 지연·파싱 + **쿼터 소진 속도** 포함.
  멀티에이전트 틱 루프는 요청을 곱셈으로 소모함.

### 8. 프레임 — AI들이 두는 보드게임의 관전, 로그라이크로 연속
- 보드게임 프레임: 틱=턴, 그리드=보드, 심판 코드=규칙서. 깊이는 콘텐츠 양이
  아니라 적은 규칙의 맞물림(카탄). 규칙은 코드 전에 종이에서 플레이테스트 가능.
- 로그라이크 프레임: 층 클리어 = 작은 끝. 영속 세계의 긴장 문제를 장르 문법으로 해결.
- 수용량: 입장은 사실상 무제한(휴면은 배치 처리), **한 층 = 한 인스턴스 = 한 파티(3~6)**.
  병목은 에이전트 수가 아니라 동시 활성 장면 수.

### 9. 설계 동결 (유효 중)
- 새 설계 금지. 이 문서는 신규 설계가 아니라 기존 층 철거(GM) + 기성품 차용의 기록.
- 진단: 코드는 과설계 아님(얇고 모범적). 문제는 설계-코드 격차. 검증 안 된 가설
  (페르소나 분화) 위에 상층 설계가 과적됨.
- 세션 규칙: 설계 세션은 새 개념이 아니라 **다음 행동 하나**로 끝난다.
  대화 재료를 "미래의 원더랜드"에서 "어제 돌린 실험 결과"로.
- 서랍(검증 후 개봉): MCP 서버 프레이밍, 수면-배치 창, 연출 정책, BYOK 키 관리 상세,
  캐릭터 커스터마이징 UI, 연금술/기습/에너지 타임라인 전체 구현.
