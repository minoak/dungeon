# 시야 엔진(Perception Engine) 설계 — 2026-07-10 세션

> PROJECT_BRIEF.md + DECISIONS_2026-07-04.md 위에 얹히는 문서.
> 7-4의 "얇은 전투 조각 + 이벤트 스키마" 작업과 어휘를 공유한다(아래 §7).
> 출발 질문: "캐릭터의 이동이 너무 비효율적인 것 아닌가" → 답은 이동 최적화가 아니라
> 지각·기억·의도 인터페이스의 설계였다.

## 한 줄 정의

세계와 캐릭터를 잇는 **막(膜)**. `(세계 진실, 관측자) → 언어 보고서`.
캐릭터는 픽셀 게임 위에 서 있지만, 픽셀로 지각하지 않는다 — 보고서로 지각한다.

## 0. 입력은 렌더링이 아니라 진실

- 시야 엔진의 입력 = **격자(물리 진실) + 구역 스키마(의미 진실)**. ASCII를 파싱하지 않는다.
  ASCII도 뷰다. 뷰를 읽어 뷰를 만들지 말 것.
- 전제: 생성기가 방을 깎을 때 방 객체를 버리지 않고 `zones`로 보관(스키마-우선).
  스키마 → 격자는 일방향 컴파일. 격자를 직접 수정하는 일은 영원히 없다.
- 구역 최소 스키마: `id / 종류 / 출구들(어느 구역으로, 미탐색 여부) / 내용물 / visited`.
  desc(설명)는 빈 슬롯으로만 존재. 채우는 건 검증 ②가 자극을 필요로 할 때(서랍).

## 1. 핵심 원칙 (오늘 확정)

1. **광학은 코드.** 뭐가 보이는지(LOS, shadowcasting, 반경)는 결정론. LLM은 광학을 영원히 안 한다.
2. **사실까지만, 해석 금지.** 코드는 "spider_1이 chest_1 경로 위에 있다"까지.
   "지키고 있다"는 에이전트의 읽기. 사실/해석의 경계 = 코드/에이전트의 경계.
   해석의 틈이 페르소나의 서식지다(검증 ②의 관찰 대상).
3. **obs는 면적이 아니라 정보량에 비례.** 빈 복도 10칸 = "복도" 한 단어. 토큰 비용이
   맵 크기가 아니라 사건 밀도에 비례하게 된다(멀티에이전트 곱셈 비용의 해법).
   단, **결정 지점은 압축 금지**: 직선 구간은 길이로 접되 갈림길·문·모퉁이에서 끊는다.
   (= 그래프: 갈림길이 노드, 직선이 길이 달린 엣지)
4. **좌표 노출 금지, id 핸들로만.** 모델은 좌표를 읽지도 쓰지도 않는다.
   엔진이 `spider_1, exit_N, chest_1` 같은 안정 id를 발급, 모델은 id로만 지칭.
   위치의 인지 형태는 좌표가 아니라 주소(구역 + 랜드마크 관계). 거리 단위는 칸(허기·에너지 비용의 인수).
5. **균일 렌즈.** v1에서 모든 캐릭터의 지각 규칙은 동일. 캐릭터별 감각 차이(야간시야 등)는
   검증 ②의 교란변수 — ② 성립 이후의 서랍. "캐릭터 위주" = 캐릭터의 위치·지식 중심이라는 뜻이지
   캐릭터마다 다르게 본다는 뜻이 아니다.
6. **기억은 엔진이 캐릭터 명의로 보관.** 한번 본 것의 위치는 캐릭터별 장부가 소유.
   캐릭터는 핑(장부 항목 지칭)으로 언제든 귀환. 상태 외부화 원칙의 공간 버전(로어북 계보).
7. **기억과 시야를 섞지 않는다.** 보고서에서 "지금 보이는 것"과 "알고 있는 것"은 별도 섹션.
   정적인 것(상자·출구·계단)은 확신 기억, 움직이는 것은 "마지막 목격: N틱 전" 딱지만.
8. **기억이 틀리는 건 허용, 세계가 거짓말하는 건 금지.** 낡는 건 항상 장부 쪽.
   핑 찍고 갔더니 없음 = 버그가 아니라 드라마. 도착 시 보고 후 장부 갱신.
9. **전방 개념 없음(보류 확정).** 자기중심 라벨(앞/뒤/좌/우)은 턴을 넘으며 썩는다 —
   나침반은 무기억 에이전트의 공짜 불변량. 기습의 드라마는 회전이 아니라 지형(LOS) 비대칭
   (모퉁이·문·잠든 몬스터)에서 오고, 그건 산 규칙(픽셀 던전)에 이미 있다.
   전방은 "픽셀 던전에 없는 규칙" 서랍 — 열려면 발명 비용을 정당화할 것.

## 2. 파이프라인 (5단계)

```
세계 진실(격자 + 구역 스키마 + 엔티티) + 관측자(위치, 장부)
  ↓ ① 가시성   visible()    shadowcasting. 어느 칸이 보이나. 순수 기하.
  ↓ ② 기호화   symbolize()  보이는 것에 id 부여. 타일 → 사실(spider_1, N, 4칸).
  ↓ ③ 관계     relate()     경로탐색 기반 확실한 사실만: 막음/인접/경유.
  ↓ ④ 기억     remember()   발견을 캐릭터별 장부(구역 그래프 + 목격물)에 병합. 안개 갱신.
  ↓ ⑤ 직렬화   serialize()  압축 규칙 적용, 보고서 생성.
  → obs
```

- **상태는 ④에만 산다.** 나머지는 순수 함수. 같은 세계·같은 관측자 → 같은 출력.
- 테스트 절단면: ①~③ 골든 테스트(시드 고정 던전 + 위치 → 기대 보고서),
  ④ 상태 전이 테스트, ⑤ 스냅샷 테스트. LLM 없이 전부 검증 가능.
- **⑤는 교체 가능한 직렬화기.** ascii_view 유무, 방향 유무 등 모든 obs 논쟁이
  ①~④ 불변인 채 ⑤의 변종 스위치가 된다. → §8 A/B 목록.

## 3. 막의 양방향성 — id 레지스트리가 심장

- 지각(세계→에이전트)과 **액션 해석기**(에이전트→세계, `goto(exit_N)` → 좌표·경로)는
  같은 막의 두 차선. 둘 다 **같은 id 레지스트리**를 조회한다.
- 시야 엔진 작업의 실체 = 지각 함수 + id 레지스트리 + 액션 해석기 **한 벌**.
- id 안정성 계약: spider_1은 계속 spider_1 (엔진이 정체성 소유).

## 4. obs 스키마 v1 (초안)

```json
{
  "you": {"zone": "room_C", "hp": "...", "near": "exit_N까지 2칸"},
  "visible": [
    {"id": "spider_1", "kind": "거미", "dir": "N", "dist": 4,
     "notes": ["chest_1 경로 상"]},
    {"id": "chest_1", "kind": "보물상자", "dir": "N", "dist": 5}
  ],
  "known": {
    "zones": [
      {"id": "room_A", "exits": [{"to": "room_C", "id": "exit_S"}],
       "seen": [{"id": "chest_0", "kind": "보물상자", "static": true}]},
      {"id": "room_C", "exits": [{"id": "exit_N", "to": "미탐색"},
                                  {"id": "exit_E", "to": "room_D", "visited": true}]}
    ],
    "last_seen": [{"id": "wolf_2", "zone": "room_D", "ticks_ago": 12}]
  }
}
```

- `visible` = 현재 시야(방향+거리+관계사실). `known` = 장부(구역 그래프 + 정적 목격물 + 낡은 목격).
- 관계사실(notes)은 판단 직결 관계만 최소로: 막음/인접/경유.
- 방향+거리는 범용 기하 기층으로 유지 — "지킨다"가 필드에 없는데 읽히는 창발의 재료.
  (같은 방향 + 더 가까움 → 사이에 있음을 에이전트가 스스로 읽는 것이 관전 포인트)

## 5. 이동 문법 — 핑 + 자동 이동 + 사건 인터럽트

- 액션 = 대상 선택(오브젝트 클릭): `goto(id)`, `explore(zone)`, `attack(id)` 등.
  바닥 클릭(자유 좌표)은 1차 동사가 아님 — 필요해지면 나중에 여는 서랍.
- `goto`의 대상: `visible`의 id(시야 안 핑) + `known`의 id(시야 밖 핑, 장부 참조 귀환).
- 경로 집행은 코드(발견한 구역 위 경로탐색). **사건 시 심의 승격**: 새 적 조우, 새 구역 진입,
  첫 피격, HP 선 통과 — 7-4의 상태 전이 승격 목록과 동일 구조를 이동에 적용.
- 루프: 지각 → 목표 선택 → 자동 이동 → 사건이 끊음 → 재지각. 콜 밀도 = 사건당.
- reason 필드가 걸음 단위 소음("북쪽이 미방문이라")에서 의도 단위 텍스트("출구보다 보물이 먼저다")로
  승격 — 구조화 로그의 최중요 텍스트 품질이 여기서 결정된다.

## 6. 검증 ③과의 접속 (설계만 기록, 구현은 서랍)

장부가 캐릭터별이므로 지식이 **거래 재화**가 된다: "출구 위치 알려줄게" = 장부 항목이
봇1 장부에서 봇2 장부로 복사되는 역학. 협상·협력·배신(거짓 위치 전달)의 재료가 여기서 나온다.
구 레이어 3 "봇끼리 대사"가 "페르소나끼리 협상"인 이유의 구조적 근거.

## 7. 이벤트 스키마와 쌍둥이

②③의 출력(id 체계 + 관계 술어)이 곧 이벤트 스키마의 어휘다.
obs = 사실층의 "지금" 직렬화, 이벤트 = 같은 어휘의 "방금 일어난 변화" 직렬화.
시야 엔진의 어휘를 잡는 순간 7-4 로드맵 2번(이벤트 스키마) 절반이 같이 끝난다.
→ 두 스키마는 반드시 한 벌로 설계할 것.
