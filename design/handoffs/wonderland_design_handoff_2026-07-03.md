# 원더랜드 설계 핸드오프 (2026-07-03 세션)

> 대상: Claude Code. 이 문서는 claude.ai 설계 세션의 결정 사항 요약이다.
> 기존 문서(DESIGN_v0.1.md, 6월 플레이어봇 세션)의 후속이며, 충돌 시 이 문서가 우선한다.

---

## 0. 프로젝트 정체성 (한 문장)

**원더랜드는 게임이 딸린 멀티테넌트 에이전트 하네스다.**
사용자는 API 키(뇌)와 페르소나 시트(영혼)만 가져오고, 신경계 전체 — 관측 포맷, 각성 시점, 기억, 반사 실행 — 는 서버 소유 하네스가 담당한다.

- 장르: BYOK 방치형 에이전트 MMOTRPG
- **결정: 키 온리.** 사용자 에이전트 코드 지참(외부 봇 API 접속)은 지원하지 않는다. 하네스 소유권이 모든 품질 보장의 전제.

## 1. 불변 원칙 (기존 확정 + 이번 세션 재확인)

1. **단일 권위 상태.** 하드 상태(HP, 인벤토리, 위치, 태그)는 코드가 소유. LLM은 서술만 가능, 변경 불가.
2. **인지는 코드, 판단만 LLM.** 액션은 의도 단위. 실행·판정·인지는 코드.
3. **GM = 코드 심판.** 모든 도구 호출은 코드 심판을 통과해 실행된다.
4. **이중 렌더러.** 에이전트용 구조화 텍스트 관측 / 소유자용 큐레이션 뷰.

## 2. 페르소나 시스템

- 사용자 경험 구조: **작가 → 관찰/양육.** 1:1 상대역(RisuAI형)이 아니라 캐릭터를 세계에 보내고 지켜보는 구조.
- **페르소나 컴파일:** 자유 서술 시트를 캐릭터 생성 시 일회성 LLM 파싱으로 하네스 파라미터로 변환.
  - 산출물: 인터럽트 임계값(위험/이득 민감도), 기본 정책 성향, 초기 갬빗 세트, 지식 예산, 수면 스케줄.
  - **컴파일 확인 UX(세션 제로):** 파싱 결과를 사용자에게 되돌려 보여주고 수정→재컴파일. 파싱 오류를 생성 UX로 흡수.
- **페르소나 ≠ 능력치.** 페르소나는 행동 파라미터로만 컴파일. 스탯으로 절대 흘러가지 않는다(밸런스 게이트).
- RisuAI 카드 임포트: 지원하되, 행동 성향 정보 부족 시 보충 질문 흐름 필수(카드는 1:1 대화용으로 최적화돼 있음).

## 3. 실행 루프 — 결정점 기반

게임의 기본 단위는 틱이 아니라 **결정점**. 에이전트는 인터럽트 발생 시에만 깨어난다.

**호출 스펙트럼 (비용-자율성 교환비가 호출 횟수 축에 정렬):**

| 층 | 호출 | 내용 |
|---|---|---|
| 0회 | 갬빗 반사 | 조건-행동 규칙이 코드로 처리. LLM 미호출 |
| 1회 | 인터럽트 반응 | 시스템이 상황을 먼저 알고 맞는 핫바를 사전 로드해서 깨움 |
| 2회 | 자발적 전환 | 에이전트가 먼저 의도를 세움 → search_actions 질의 → 실행 |

- 반응은 싸고 주도는 비싸다. 방치형에서 지배 항은 1회 경로.
- **3층 자동화** (시스템1/2 대응): 반사(코드, 컴파일 파라미터) / 정책(갬빗 — 에이전트가 결정점·수면에 자기 저작·개정) / 숙고(LLM).
  - 자유도 기준: 제어 granularity가 아니라 **정책의 저작권.**
- **각성 예산:** 소유자가 하루 결정 횟수 상한 설정. 소진 시 보수적 기본 정책(귀환/대기). 지출을 사고가 아닌 선택으로.
- **v0 인터럽트 대분류 3종: 전투 / 조우 / 목표상태변화.** 나머지 이벤트는 로그 큐잉.

## 4. 리모컨 = 네이티브 Tool Calling

- 액션은 관측 텍스트 내 목록이 아니라 **자기 서술적 도구 스키마**로 노출. BYOK에서 모델 불문 유일한 공통 훈련 인터페이스가 tool use이기 때문.
- **월드 서버 = 게임 규칙을 강제하는 MCP 서버**로 설계.
- **핫바:** 상황별 도구 대여섯 개, 인터럽트 분류의 부산물로 코드가 사전 로드(무료). 에이전트가 자기 핫바를 재배치 가능(정책 저작권 3번째 적용).
- **스펠북:** `search_actions(query)` 도구. 전체 카탈로그 접근권. 질의 방식이라 트리 탐색 불필요.
  - 트리는 에이전트가 걷는 길이 아니라 시스템의 분류 서랍장(카테고리 태그: 전투/사회/탐색/생존). 상황별 기본 핫바 생성 규칙과 신규 버튼의 꽂을 자리를 정의.
- 도구 `설명` 필드 = 페르소나 넛지 채널(렌더링 두께·순서 가중).
- **자유서술 액션(`시도한다`)은 v0 제외.** 대신 **기각 로그**를 남겨 다음 버튼의 수요 조사로 사용(헌법을 판례로 개정).

## 5. 태그 시스템

- 캐릭터 시트 = **append-only 원장.** 불변 코어(소유자 저작, 생성 시 봉인) + 가변 태그층(세계가 부여).
- **발급 권한: 시스템 독점.** 코드가 감지 가능한 조건에서만 발화(예: 관계 태그 = 양측 의도 선언 매칭, 칭호 = 이벤트 로그 조건). LLM·사용자 모두 수정 불가.
- 모든 태그에 **출처 증명**(발화 이벤트 역추적 링크).
- 수명 축 분류: 영구 칭호 / 관계(해제 조건 有) / 일시 상태(자동 만료). 태그 연쇄(해제→새 상태 발화)는 규칙 소수로 시작.
- **아키텍처 절단(신 객체 방지):** 아래층 = 얇은 프리미티브(타입·출처·수명을 가진 append-only 항목). 위층 = 독립 서브시스템들(관계 상태 / 지식 열쇠 / 로그 인덱스)이 같은 프리미티브를 공유.
- 태그 = 로그 인덱스: 태그 발화 시점 주변만 고해상도 보존, 무태그 구간은 통계 압축. 큐레이션 뷰 = 신규 태그 목록 + 발화 장면.

## 6. 지식 시스템

- **지식 본문은 월드 로어 DB(코드 소유 정본), 태그는 열쇠.** 주입은 관측 생성 시 엔티티 키 조인(v0는 시맨틱 검색 불필요, bge-m3는 추후).
- 축적 무해: 태그 200개여도 주입은 맥락 필터링이라 컨텍스트 불폭발.
- 몰두 방어는 지형 설계: **수확 체감**(읽은 책 재독 무효, 장소당 지식 유한) + **공간 분포**(새 지식은 던전·대화·이벤트에 산포) → 지식욕이 탐험을 강제.
- **풍문 2등급 태그:** 대화로 전달된 지식은 "A가 주장함: ..." 형태의 출처 박힌 미검증 항목. 검증 조건 충족 시 정식 승격, 거짓 판명 시 신뢰 태그 변동. → 거짓말·정보 사기가 환각 방화벽을 뚫지 않고 게임플레이가 됨.
- **다중 트리거 처리(로어북 직수입):** 관련도 점수(엔티티 근접도, 최근 사용, 등급, 페르소나 가중 — 풍문은 출처 인물 등장 시 급상승) → 상위 N개만 주입, N = 토큰 예산.
  - `recall(주제)` 도구 = 지식의 스펠북(능동 회상, +1 호출). 자동 주입 = 프라이밍(무료).
  - **재귀 깊이 1로 잠금**(로어북 재귀 폭주 방지).

## 7. 시간

- **시간 배율 = 토큰-서사 환율.** 소유자 하루 지출 상한에서 역산해 결정.
- **필수 방어 설계: 콘텐츠는 전부 월드시간 단위로 저작, 배율은 변환 레이어로 분리.** 실시간 하드코딩 금지. 배율은 서버 노브.
- 후보: 2:1 vs 3:1(둘 다 24h 정수 배라 접속 위상 결정론적). 3:1은 서사 밀도(3장/일) 유리, 고정비 1.5배. **판정은 동일 시나리오 A/B 런 후 산출 기록 대독.**
- **잠 = 보장된 배치 윈도우:** 비치명 인터럽트 큐잉→기상 시 일괄 관측, 갬빗 개정 실행 시간, 취약성 윈도우(야영 위치가 결정이 됨). 수면 스케줄은 전역 고정이 아니라 캐릭터별(페르소나 컴파일 산출).

## 8. 세계

- 생동감 = 연출이 아니라 **흔적의 지속.** 에이전트 행동이 읽을 수 있는 상태 변화를 남기는 것(빈 선반, 시체, 열린 문). 전부 상태 테이블 조작, LLM 비용 0.
- 세계 시뮬레이션은 자원 틱 수준(리스폰, 재생)이면 충분.
- **rndbot 역할 재정의: 월드 채우기가 아니라 흔적 생산자.** 콜드스타트 바닥.
- 방 템플릿에 훅 구조 배치(위험/이득/미스터리 신호) — 페르소나가 갈라질 여지를 코드 레벨에서 심는 순수 콘텐츠 설계.

## 9. 보류 / 제외 / 추후

| 항목 | 상태 | 비고 |
|---|---|---|
| 에이전트 일기 | **보류** | 압축은 코드 통계 요약으로 대체. 태그가 큐레이션 골격 대행. "어떻게 그렇게 됐는지"의 결이 아쉬워지는 시점에 재검토 |
| 자유서술 액션 | v0 제외 | 기각 로그 = 수요 조사 |
| 로어북 재귀 | 깊이 1 잠금 | 필요 시 개방 |
| PK | 추후 | 구역별 규칙 + 죽음은 소멸이 아닌 비용. 방치형 특유의 "부고 문제" 유의 |
| 주관(페르소나 렌즈) 관측 | 추후 | v0는 객관 구조화 관측. 프리미엄 층 후보 |
| 시맨틱 지식 검색 | 추후 | v0는 엔티티 키 조인 |

## 10. v0 발주서

**목표: 기능 완성이 아니라 박동수 찾기.**

- 에이전트 5마리, 한 구역, 실시간 하루
- 태그 20개 미만 (하중 받는 서브시스템은 캐릭터 상태 + 지식 열쇠 둘뿐)
- 인터럽트 3종(전투/조우/목표상태변화) + 갬빗 반사
- 핫바 사전 로드 + search_actions 스펠북
- 시간 배율 노브 구현 → 2:1 / 3:1 동일 시나리오 A/B
- **합격 기준: 하루 돌린 활동 기록(태그 발화 + 발화 장면)이 사람이 읽을 만한가.** 판정은 숫자가 아니라 민옥의 눈.

## 11. 판단 근거 요약 (Claude Code가 알아야 할 "왜")

- 비용 제약(BYOK 토큰)이 설계를 나쁘게 만든 게 아니라 결정점 루프·3층 자동화·핫바를 강제했다. 포도당→시스템1/2와 같은 수렴 진화.
- 심즈와의 분기: 심즈는 상태→행동(효용 함수), 원더랜드는 행동→상태(기록). 반(反)심즈 예산은 갬빗 자기 저작 + 에이전트 간 언어 채널에 있다. 언어 채널은 환각 리스크와 동일 채널이지만, 하드 상태 코드 소유 원칙이 방화벽 — 속는 에이전트는 오염이 아니라 사기 게임플레이.
- 계보: 벨라도나(Lua 하네스, 1:1 페르소나 유지) → 원더랜드(멀티테넌트 하네스, 자율 에이전트 페르소나 유지). 로어북 우선순위·호감도 매트릭스 등 기존 검증 패턴을 직수입한다.
