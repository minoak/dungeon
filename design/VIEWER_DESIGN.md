# VIEWER_DESIGN — 웹 타일 뷰어 (라이브 + 리플레이)

> 2026-07-05 개설. 렌더링 3단계 서랍(HARNESS_DESIGN.md D11 보류 메모)의 ①ASCII→②타일 구간 개봉.
> 위치 근거: ④월드 러너는 헤들리스라 뷰어 없이는 첫 가동을 눈으로 검증할 수 없다 — 뷰어가 관전 창구의
> 선행 재료. 이 물건이 서면 tmux는 "옵션 렌더러"로 강등된다(설계 원문 그대로의 실현).

## 1. 무엇인가

**stream.jsonl 을 읽어 브라우저 캔버스에 타일로 그리는 관전 창구 한 장.**
라이브와 리플레이는 기능 두 개가 아니라 같은 뷰어의 재생 모드 두 개다:

- **리플레이** = `runs/` 에 보존된 끝난 판을 처음부터 스크럽 (일시정지·배속·틱 시킹)
- **라이브** = 지금 자라는 `state/stream.jsonl` 을 꽁무니에서 따라 읽기

읽는 파일 형식이 같으므로 그리는 코드는 하나. 풀판(153틱) = 400KB — v0 은 통째 읽기로 충분.

## 2. 원칙 (전부 기존 헌법에서 상속)

- **순수 소비자**: 엔진·스트림 무수정. 뷰어는 GM·기계 크로니클·보고서와 형제(STREAM_FORMAT 첫 줄 구조).
  스트림에 필드가 필요해지면 additive 로만.
- **판정은 영원히 그리드, 봇의 obs 는 영원히 텍스트**: 뷰어는 겉옷이다. 게임 규칙·에이전트 인터페이스 불변.
- **관전자 등급 진실**: 스트림엔 숨은 함정·매복몹·숨은 보물이 다 있다(계약 ⚠️). 뷰어는 관전자 전용이므로
  이를 **그린다**(반투명 등 구분 표시 = tmux 가 매복몹을 'm' 으로 그리던 극적 아이러니의 계승).
  이 화면을 봇에게 보여주면 시야-온리 계약이 깨진다 — 봇용 뷰 아님.
- **모르는 필드·모르는 kind 는 조용히 무시** — 단 스프라이트는 "무시=안 그림"이 정보 소실이므로
  미지 kind → **제네릭 폴백 스프라이트**로 그린다(마을 등 새 kind 가 와도 뷰어 수정 없이 뭔가는 보임).
- **에셋은 CC0 전용.** SPD/픽셀 던전 에셋은 GPLv3 — 코드를 복붙 안 한 것과 같은 이유로 그림도 금지
  (서비스 지향 상수). 채택 전 팩의 라이선스 문구 실물 확인 1회.

## 3. 구조

```
~/dungeon/viewer/
  index.html      ← 한 파일 앱(HTML+CSS+JS 인라인, 외부 CDN 없음 — report.py 산출물과 같은 자체완결 스타일)
  tiles.png       ← CC0 타일셋 시트(1~2장)
  tiles.json      ← kind/type/job → 스프라이트 좌표 매핑(코드가 아니라 데이터 — 새 개체는 여기만 추가)
```

- **서버**: `cd ~/dungeon && python3 -m http.server 8000` → 브라우저 `http://localhost:8000/viewer/`.
  dungeon 루트에서 띄우므로 `/runs/…`, `/state/stream.jsonl` 이 전부 fetch 가능. 전용 서버 코드 없음.
  (Windows 브라우저 ↔ WSL localhost 는 기본 포워딩으로 통함.)
- **판 선택**: URL 파라미터 `?run=runs/watch-…/stream.jsonl` / 무파라미터 = `state/stream.jsonl` 라이브.
- **라이브 tail**: 주기 fetch(1~2s, cache-bust) 후 전체 재파싱. 마지막 라인이 개행으로 안 끝나면 미완성
  라인 — 버린다(계약의 tail 소비 규칙 그대로). 증분 읽기(HTTP Range)는 성능 문제가 실측될 때만.

## 4. 렌더 규칙 (STREAM_FORMAT 이 이미 정해둔 것들)

1. **베이스** = `level.grid`(raw 지형 `#`/`.`) 위에 `features → traps → monsters → bots` 순서로 겹쳐 그리기
   ("겹쳐 그리기는 소비자 몫" — 계약 명문).
2. **조인은 파일 순서로**: tick 은 파일 순서상 직전 level 에 속한다. **turn 으로 tick↔level 조인 금지**
   (강하 턴은 옛 층 좌표 — 계약 ⚠️. 어기면 벽 속 봇이 나온다).
3. **틱 시킹 공짜**: tick 의 bots/monsters/features/traps 는 전체 스냅샷(델타 아님) — 슬라이더로 임의 틱 점프.
4. **발자국** = 파생 규칙대로 level.party 스폰 칸 + 이후 각 tick 봇 좌표 누적(바닥 톤 변화로 표시).
5. **표시 클램프**: 사망 몹 스냅샷 hp 는 음수일 수 있음(raw) → 0 클램프. alive:false 봇/몹 = 시체 스프라이트.
6. **대사·속내**: say = `decisions[].say`(skipped 제외 — 파생 규칙), reason = 피드에 병기.
   보고서 설계의 "reason = 제품에서 가장 중요한 텍스트"를 뷰어에도 적용 — 페르소나가 보이는 곳.

## 5. 화면 레이아웃 — tmux 5분할의 이식(검증된 원형)

```
┌────────────────────────────┬──────────────┐
│                            │ 파티 패널     │  ← 캐릭터별: 이름·직업·HP바·bag·
│   타일 맵 (캔버스)          │ (두란/카야/   │     현재 order(뭘 하려는지)
│                            │  피른)       │
│                            ├──────────────┤
│                            │ 이벤트 피드   │  ← events 문장화(기계 크로니클 어휘)
│                            │ + say·reason │     + 말풍선. 전투/발견 굵게, 이동 흐리게
├────────────────────────────┴──────────────┤     (보고서의 DF/EVE 문법 재사용)
│ 재생 컨트롤: ◀ ▶ ⏸  배속 1×/4×/16×  [틱 슬라이더]  t92/153  층 1/2  │
└───────────────────────────────────────────┘
```

- GM(LLM) 내레이션은 **스트림에 없다**(gm.log 는 별도 소비자 산출물) → v0 범위 밖. 원하면 후순위 additive.

## 6. 타일셋 — CC0 후보와 필요 스프라이트

후보(구현 세션에서 실물을 나란히 띄워 민옥 눈으로 선정):
- **Kenney Tiny Dungeon / 1-Bit Pack** — CC0, 세트 통일감, 16×16
- **DCSS(Dungeon Crawl Stone Soup) 타일** — CC0, 로그라이크 몹 어휘 풍부(고블린·거미류 1:1), 32×32

필요 목록(현 스트림 어휘 전수 — tiles.json 의 키가 됨):
- 지형: 벽 / 바닥 / 발자국 바닥 / 계단(`>`)
- 봇: 전사·도적·음유시인(job 기준) + 시체. 낯선 job → 제네릭 모험가
- 몹: 고블린·그림자거미(kind 기준) + 시체. concealed=반투명. 낯선 kind → 제네릭 몹
- 함정: spike/dart/alarm × (hidden=관전자용 반투명 / 드러남 / sprung=발동 후)
- 피처: treasure/chest/fountain (concealed=반투명)
- 타일 로드 실패 시 글리프(문자) 폴백 — 뷰어가 그림 없이도 죽지 않게

## 7. 빌드 단계 (MVP 사다리)

| 단계 | 내용 | 합격 기준 |
|---|---|---|
| **V1 리플레이** | 판 하나 로드 → 타일 렌더 + 재생/일시정지/배속/슬라이더. 표본 = `runs/watch-20260705-1324/`(t153 전멸판 — 매복·도주·강하·전멸이 다 있는 최적 표본) | **민옥 눈**: "tmux 대신 이걸로 보겠다" 판정. 정합은 같은 판 tmux 글리프와 수동 대조 1회 |
| **V2 라이브** | `state/stream.jsonl` 폴링 — 진행 중 판 따라가기 (start.sh 는 그대로, 브라우저만 추가로 열기) | 라이브 1판을 뷰어로 완주 관전 |
| **V3 연출** | 칸 사이 보간 애니메이션·피격 플래시·말풍선 연출 (렌더링 3단계의 ③) | 후순위 — V2 안착 뒤 |

- 자동 verify 게이트는 **만들지 않는다**: 뷰어는 판정 무관여 순수 소비자라 기존 10종과 직교.
  (검증 체인에 안 끼움 — state/ 사고 교훈: 관전 도구가 검증 스위트에 섞이면 오인 실행 표면이 는다.)
- 검증②(같은시드 시트 교차)와 서로 안 얽힘 — 순서 자유. 뷰어가 서면 검증②·월드 러너의 관전도 이걸로.

## 8. 안 하는 것 (v0 비스코프)

- 접속 층·계정·배포(서랍 휴면 그대로 — 이건 localhost 물건), 봇용 필터 뷰, GM 내레이션 표시,
  엔진·스트림 수정, GPL 에셋, 게임 콘텐츠 추가(Part C 는 별도 단계).

**실물**: `viewer/index.html`(한 파일 앱) + `viewer/tiles.json`(매핑 데이터) + `viewer/assets/`.
실행(원커맨드, 2026-07-05 민옥 합격 판정 후 통합):
- `bash ~/dungeon/live.sh` — 헤들리스 라이브: 지난 판 보존 → 뷰어 서버 보장(멱등) → 게임 실행.
  GM 기본 0(뷰어에 GM 칸 없음). 관전=브라우저만.
