- **B — 개정안 v0.1**: [개정 프롬프트 전문](adventurer_prompt_compose_v0.1.md). A의 구조에 기존 캐릭터·기억·세계 규칙을 연결한 고정 지침 초안이다. 이 파일 본문이 캐릭터에게 전달할 후보이며, 이 비교 문서의 개발 메모는 전달하지 않는다.

원본 지시서: `C:/Users/akals/Documents/카카오톡 받은 파일/WONDERLAND_COMPOSED_ACTION_SYSTEM_2026-09-10_v0.4.md`.

**B는 v0.4의 행동 문법을 유지한 개정안이다. 첫 프로브의 임시 어휘는 아래에 별도로 제안한다.** 문장을 다듬은 차이와 엔진 기능을 덜어낸 차이가 섞이지 않도록 했다. 지시서의 전체 구현 순서나 확정 계약을 이 문서로 바꾸지 않는다.

## 문구와 구성의 차이

| 항목 | A — 지시서 예시 | B — 개정안 | 이유와 영향 |
|---|---|---|---|
| 캐릭터 판단 | 예시 바깥 §6·§26에서 상황·성격·기억 → reason → 행동과 말을 정의 | 첫 문단에서 시트·기억을 바탕으로 행동과 의사소통을 함께 결정하도록 명시 | 설계 의도를 실제로 전달되는 지침 안에 둔다. 직업별 목표를 자동 부여하지 않는 기존 결정도 유지 |
| 행동 사전 | 짧은 COMMON 10종과 SKILL 자리 | 같은 10종을 유지하고 각 행동에 필요한 필드를 함께 설명 | 뜻과 출력 사용법을 한곳에서 읽는다. 특정 행동을 언제 골라야 하는지는 추가하지 않음 |
| 행동과 말 | 판단 공간에 함께 제시, 병렬 관계는 §6에서 설명 | 병렬 판단을 첫 문단에 명시하고 `target`과 `to`가 달라도 됨을 설명 | 물건을 쓰는 대상과 말하는 상대를 혼동하지 않게 함 |
| 자유로운 시도 | “가능 여부와 결과는 세계가 판정한다” | 실패·무변화도 결과임을 적고, 자유 서술로 물리 결과·상대 감정을 확정하지 않도록 설명 | 시도와 결과의 경계를 지킴. 기괴한 행동 예시를 반복해서 특정 조합을 유도하지 않음 |
| ID와 기억 | `self`, way ID, 기억 규칙이 여러 절에 분산 | `self`, 이번 관측의 way ID, 기억은 마지막 위치라는 사실을 한곳에 모음 | 참조 문법을 읽을 수 있게 함. 모르는 대상까지 아는 권한을 주지 않음 |
| 제안 | §15에는 잡담·제안 이름만 있음 | 말 전달과 재판단 요청의 차이, 수신자와 회의 범위를 설명 | 제안을 “질문일 때만”으로 좁히지 않고 기존 “상대의 선택을 요청” 의미를 유지 |
| 반응 | §8의 예시에 reaction과 reaction_to가 항상 함께 등장 | 받은 사건 하나를 선택적으로 평가하며, 생략과 수락·거절의 구분을 설명 | 근거 없는 사건 ID와 의무적인 양자택일을 줄이려는 의도. 효과는 아직 미측정 |
| 출력 예시 | use 예시에 then·say·form·reaction·note를 모두 넣음 | 최소 유효 예시를 두고 조건부 필드는 해당 설명에 배치 | use에도 form을 항상 붙여야 한다는 오해를 줄임. 필드 종류 자체를 삭제한 것은 아님 |
| 기존 기억 | note만 대표 예시에 있음 | note·relation_line·floor_line을 조건과 함께 유지 | 프롬프트 교체 때문에 현재의 기억 작성 기회가 사라지지 않게 함 |
| 세계 전제 | 사실형 전제를 별도 A/B 대상으로 예약 | “계약 없이 만난 모험가” 등의 전제 문구를 넣지 않음 | 행동 문법 실험과 세계 전제 실험의 변수를 분리 |

B에서도 COMMON을 대상마다 걸러서 완성된 선택지로 만들지 않는다. 독립 행동·사회 행동의 빈도를 올리라는 명령, 다양하게 행동하라는 명령, 친목 형태 목록은 추가하지 않는다.

## 매 턴 판단 공간 예시

아래는 A의 §15 예시를 그대로 쓴 **설명용 가상 장면**이다. 실제 관측이나 플레이 결과가 아니다. A와 B를 문구로 비교할 때 대상·상태·기억은 같은 것을 사용한다.

```text
## 판단 공간

대상
- m1: 고블린 — N 2칸
- c1: 닫힌 문 — E 1칸
- f2: 상자 — SW 3칸
- b2: 카야 — W 1칸
- w1: 동쪽 통로 — E 4칸

소지
- i1: 회복 물약

행동
COMMON: goto / follow / explore / search / attack / use / give / bond / wait / rest

의사소통
- 잡담
- 제안
```

실제 연결에서는 기존 `_wire()`의 공간 구조·방위·거리·관측과 기억의 구분을 유지한다. 이 짧은 예시로 관측 전체를 대체하지 않는다. 행동·의사소통 요약을 현재 대상과 가까이 배치하고, 완성 행동 번호 목록은 붙이지 않는다.

`c1`·`i1` 등은 지시서 예시의 이름이다. 실제 엔진이 준 ID를 그대로 표시한다. 특히 현재 문 ID는 `d...`이므로 예시에 맞추기 위해 실제 ID를 바꾸지 않는다.

메뉴에만 들어 있던 사실은 관측 쪽으로 옮길 필요가 있다. 예를 들어 무기의 피해 보너스·장비 교체 효과·계단 이용 조건은 행동 추천이 아니라 선택에 필요한 세계 정보다. 번호 목록을 빼면서 이 정보까지 잃으면 비교가 달라진다.

## 첫 플레이 프로브에 적용한 임시 차이 — 2026-09-10 후속 연결

대화에서 정한 첫 순서는 “프롬프트와 최소 연결부를 바꾸고 먼저 플레이한다”다. 위 B는 v0.4 전체 문법을 설명하므로, 현재 엔진에 그대로 연결하면 실제 기능과 맞지 않는다. 첫 프로브용 실행 파일에는 다음 차이를 두었다. 이는 v0.4 최종 설계를 폐기하는 결정이 아니다. 아래 코드 관계 설명은 연결 전 검토 기록이며, give/bond 직접 출력과 b2 표시는 후속 연결에서 보완했다.

| 부분 | B의 v0.4 문법 | 첫 프로브에 제안하는 적용 | 현재 코드와의 관계 |
|---|---|---|---|
| 사용 | `use target [item]`, 자기 대상 `self` | `interact target`과 대상 없는 `drink`를 우선 사용 | interact는 기존 피처·계단 상호작용, drink는 자기 물약 소비. 몬스터에게 물약 효과를 주는 기능은 새 구현 영역 |
| 조사 | `search target` | 대상 없는 `search`: 현재 자리 주변의 숨은 것을 수색 | 현재 `_search()`는 대상 ID를 받지 않음. `search self`라는 새 의미도 이번 문서에서 확정하지 않음 |
| 탐색 | `explore w1` | 현재 탐색 후보의 방향을 쓰는 `explore E` 또는 대상 생략 | **v0.4의 Phase 1 way ID 요구와 다른 선행 프로브 제안**이다. 먼저 방향형으로 시험한다면 그 차이를 실험 기록에 남기며, Phase 1 계약 충족으로 보고하지 않음 |
| 자동 접근 | 실행 거리까지 접근 후 원래 행동 수행 | “이동은 goto로 선택하며, 다른 행동은 현재 자리에서 시도한다. 거리 밖이면 실패할 수 있다”로 이동 설명 교체 | 접근 resolver의 완성을 첫 플레이 전제에 추가하지 않음 |
| 건네기·친목 | `give target item`, `bond target form` | 기존 엔진 동사를 유지. item은 `potion / weapon / armor`, 대상은 현재 구현이 처리하는 동료 | 엔진에는 있지만 자유출력 파서에는 연결이 필요함. 이 초안만 교체해서 즉시 실행 가능하다는 뜻이 아님 |
| 후속 계획 | 같은 행동 객체 최대 2수 | 현재 객체 파서가 처리하는 `goto / attack / interact / search / explore`만 안내 | 기존 `_then()`·`plan_step()` 제약. give의 item이나 bond의 form이 계획에서 유실되는 경로를 보편 지원으로 설명하지 않음 |
| 반응 | 사건 ID를 가리키는 reaction | 사건 ID 배달·수집 연결 전에는 반응 안내를 제외 | 기존 replies는 반응의 외형 기록이며 like/dislike 기록이 아님 |

현재 자유출력 파서는 모르는 동사에 target이 붙으면 goto로 보정할 수 있다(`brains.py`의 `_TYPES`와 `claude_brain`). 따라서 연결 시 give/bond가 이동으로 바뀌지 않는지 확인해야 한다. 대상 표기에도 행동 ID인 `b2`를 명시해야 한다. 현재 `_wire()`의 `봇2` 표기만으로 모델이 ID 변환을 추측하게 두지 않는다.

첫 프로브에서 가능한 행동·대상 효과는 현재 엔진 수준이다. 여기서 측정할 것은 **기존 기능을 직접 조합하도록 제시했을 때의 선택 변화**다. ally 공격이나 monster 물약 사용 같은 새 효과까지 구현되었다고 해석하지 않는다.

## 길이와 검토 결과

공백·줄바꿈을 포함한 Unicode 문자 수를 파티/솔로 분기 적용 후 측정했다. 토큰 수가 아니다.

A는 부분 예시, B는 통합 지침이므로 A 발췌 총량과 B를 비교해 “경량화 성공”으로 판정하지 않는다. 고정 지침의 비교 기준은 현재 사용 중인 `adventurer_prompt_menu.md`다. 실제 입력에는 시트·관측·기억이 더해지므로 전체 입력 토큰은 연결 후 같은 장면에서 측정해야 한다.

이번 검토는 원문 발췌 일치, 예시 JSON 형식, COMMON 어휘, 파티·솔로 분기, 길이와 설명의 정합을 확인한 문서 검토다. 행동 다양성·캐릭터성·파싱 성공률의 개선은 아직 검증하지 않았다.

## 작성자 판단

A의 “대상 + 행동 + 의사소통” 구조는 그대로 가져갈 만하다. B에서 먼저 채택할 부분은 판단의 병렬성, 한곳으로 모은 행동 사용법, 최소 JSON 예시, 조건부 기억 필드다.

긴 제안·기억 설명은 정확성을 위한 보완이지만, 모델이 어떻게 읽는지는 플레이로 확인해야 한다. 첫 플레이 전에 범용 resolver·Entity 일반화를 더 설계하는 일을 선행 조건으로 추가하지 않는다.
