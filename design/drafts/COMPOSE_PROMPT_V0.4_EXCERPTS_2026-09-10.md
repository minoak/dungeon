### 14.1 행동 설명

```text
## 행동

현재 관측된 대상과 아래 행동을 자유롭게 조합하라.
어떤 행동이 현명한지는 정해져 있지 않다.
가능 여부와 결과는 세계가 판정한다.

COMMON
goto: 대상이나 위치로 이동
follow: 대상을 따라감
explore: 제시된 탐색 후보를 향해 탐색
search: 대상을 자세히 조사
attack: 대상을 공격
use: 대상 자체 또는 가진 물건을 대상에게 사용
give: 가진 물건을 대상에게 건넴
bond: 대상에게 친목 행동을 시도(form 자유)
wait: 기다림
rest: 휴식

SKILL
보유한 기술이 있을 때 이곳에 추가된다.
```

행동 사용법을 공략처럼 설명하지 않는다. **무엇을 하는지는 설명하되 언제 써야 하는지는 캐릭터에게 맡긴다.**

## 15. 매 턴 가변 프롬프트와 판단 공간

완성 행동 메뉴를 만들지 않는다.

기존:

```text
## 선택지

1. 고블린 공격
2. 문 열기
3. 상자 조사
4. 카야에게 물약 건네기
```

변경:

```text
## 판단 공간

대상
- m1: 고블린 — N 2칸
- c1: 닫힌 문 — E 1칸
- f2: 상자 — SW 3칸
- b2: 카야 — W 1칸
- w1: 동쪽 통로 — E 4칸

소지
- i1: 회복 물약

행동
COMMON: goto / follow / explore / search / attack / use / give / bond / wait / rest

의사소통
- 잡담
- 제안
```

`대상`, `행동`, `의사소통`은 **한 묶음의 판단 공간**으로 제공한다.

프롬프트상 개념은 분리하되, 실제 판단 위치에서는 서로 멀리 떨어뜨리지 않는다.

```text
대상
+
행동
+
의사소통
↓
reason을 바탕으로 한 하나의 판단
```

행동 정의의 자세한 의미는 고정 지침에 한 번만 설명하고, 매 턴에는 현재 대상과 현재 보유 행동/스킬을 짧게 제시한다.

기존 `_wire()`가 제공하는 방향/거리 표현을 우선 재사용한다.

## 8. 새로운 출력 스키마

v0.4에서는 기존 호환성을 위해 평면 구조를 유지한다.

```json
{
  "reason":"판단 이유",
  "type":"use",
  "target":"m1",
  "item":"i1",
  "then":[{"type":"goto","target":"c1"}],
  "say":"그거 한번 마셔봐.",
  "say_kind":"잡담",
  "to":"2",
  "form":"친목 행동일 때 자유 서술",
  "reaction":"like",
  "reaction_to":"social_184",
  "note":"기억해둘 내용"
}
```

필수는 `reason`, `type`이고 나머지는 조건부다. 자기 자신을 target으로 삼을 때는 `"self"`를 사용한다.

`then` 역시 같은 행동 스키마를 사용한다. 다만 자동 접근이 도입되므로 `goto target → then attack target` 같은 배관용 계획을 모델에게 요구하지 않는다. `then`은 캐릭터가 실제로 두 수 이상의 행동을 미리 계획할 때만 사용한다.

실행 시점에 세계 상태가 달라졌다면 resolver가 다시 유효성을 검사한다.
